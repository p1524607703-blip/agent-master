# Amazon Ads MCP 公网测试副本设计

## 目标

在不修改现有 `amazon-ads-local` 管理员隧道、`amazon-ads-ops-readonly`
只读隧道及其 ChatGPT 应用映射的前提下，在阿里云华东 1（杭州）创建两个
独立的 Function Compute 3.0 Web Function 测试副本。

## 已批准的约束

- 总新增按量测试费用不超过人民币 1 元。
- 不购买域名、证书、资源包，不领取任何免费试用。
- 使用 Function Compute 内置 HTTPS 测试地址；不得作为生产地址。
- 运营入口固定只加载 10 个读取工具，数据库角色固定为
  `amazon_ads_ops_reader`。
- 开发入口加载 25 个工具；两个入口分别使用独立的短时 JWT 与签名加密凭证。
- 两个公网 `/mcp` 入口均不得匿名访问；数据库密码和令牌不得进入 HCL、Git、
  日志或命令输出。FC 健康检查专用的 `/healthz` 只返回固定状态。
- 复用现有 RDS、VPC 和 VSwitch，不修改其生命周期和配置。

## 资源设计

| 资源 | 数量 | 配置 | 说明 |
| --- | ---: | --- | --- |
| FC 3.0 Web Function | 2 | 0.25 vCPU、512 MiB、最小实例 0、杭州 | 名称带 `-20260822` 的独立测试资源 |
| FC Function Version | 2 | 由验收部署包发布的不可变版本 | 防止触发器指向可变 `LATEST` |
| FC Alias | 2 | `verified-test-20260822` | 触发器只指向已发布版本 |
| HTTP Trigger | 2 | 内置 HTTPS 测试地址 | 仅测试使用 |
| FC 并发配额 | 2 | 每个函数保留/限制并发为 1 | 防止异常扩容 |
| Advanced Security Group | 1 | 默认拒绝所有出入站 | 供 FC VPC ENI 使用 |
| Security Group Egress Rule | 1 | 仅到 RDS 私网 IP 的 TCP 5432 | 禁止公网及横向出站 |

应用部署采用两阶段方式，不新建 OSS Bucket，也不创建 RAM 执行角色。阶段一由
IaC 创建禁用调用的函数、隔离网络和并发上限，函数只包含无法启动网络服务的失效关闭
占位包；
阶段二通过 Function Compute UpdateFunction API 只更新代码包，成功校验包摘要后，
再由同一 IaC 远程状态创建不可变版本、别名和 JWT 触发器。Terraform 对函数 `code`
设置 `ignore_changes`，避免后续计划把 API 上传的真实代码回退为占位包。函数和
Terraform 只保存两把 Ed25519 公钥；JWT/请求签名私钥留在本机钥匙串。数据库密码
每次请求时先用函数实例的临时 X25519 公钥加密，再由本机私钥签名，解密值仅存在
于该 ASGI 请求的内存上下文中，不进入函数配置、Terraform 状态、文件或日志。

## 网络拓扑

`测试客户端 -> FC 内置 HTTPS -> FC 网关 JWT 校验 -> 签名加密请求凭证校验 -> 独立 MCP Server`

`FC -> 新 Advanced Security Group -> 现有 VSwitch/VPC 内网 -> 现有 RDS PostgreSQL 私网 IP:5432`

只读函数和管理员函数分别运行，工具注册表、数据库角色和访问令牌均相互隔离。

## 权限边界

### 运营测试函数

- 工具：10 个只读工具。
- 写工具：0。
- 数据库管理员工具：0。
- 数据库连接：`default_transaction_read_only=on`、10 秒 statement timeout。

### 开发测试函数

- 工具：25。
- 只读查询、14 个受控写入工具、1 个数据库管理员工具。
- 高风险数据库操作继续要求现有确认短语并写入审计。
- 本轮云端管理员 SQL 的 statement timeout 额外限制为 20 秒，低于函数 30 秒超时，
  确保数据库先终止再由函数返回结果。
- 常规查询/受控写入使用 `codex_reader`；唯一的管理员 SQL 工具单独使用
  `amazon_ads_admin`，两组角色密码分别注入。
- 数据库管理员审计的权威记录写入 RDS `chatgpt_ops.admin_sql_audit`；`/tmp`
  JSONL 仅为当前实例的补充记录，不作为持久审计源。

## 安全设计

- 首阶段为两个入口分别使用最长 5 分钟的 EdDSA JWT。FC 网关通过公开 JWKS 在
  函数执行前拒绝无效请求，两个入口的私钥互不共用。
- 数据库密码放入第二层 Ed25519 签名、X25519 协商、AES-256-GCM 加密的短时请求
  信封，通过 `X-Ads-Test-Envelope` 传输；函数冷启动会轮换临时解密密钥。
- 健康检查不返回数据库、账号或令牌信息。
- MCP 请求必须同时带 `Authorization: Bearer <JWT>` 与加密请求信封；任一校验失败
  均不能进入工具执行。
- 运营函数只注入 `amazon_ads_ops_reader` 密码；管理员函数按用途分别注入
  `codex_reader` 与 `amazon_ads_admin` 密码，避免角色串用。
- 函数禁止公网出站；因此本轮不会调用需要下载公网报告文件的管理员导入工具。
- 正式上线前替换为 OAuth 2.1/Auth0、开发人员白名单与自定义已备案域名。

## 成本控制

- 两个函数最小实例数为 0、单实例并发为 1、函数级并发配额为 1、单次超时 30 秒。
- 不创建日志服务、WAF、ALB、NAT、EIP、OSS 或常驻实例。
- 固定验收上限为每个入口各 1 次未授权检查、1 次初始化/工具列表和 1 次只读
  数据库查询；不执行写入或管理员 SQL。
- 验收完成后立即停用入口、销毁测试资源并删除两把本机测试私钥。云平台不提供按人民币金额
  自动熔断，因此以并发封顶、固定调用次数和短生命周期共同控制费用。
- 若平台提示购买、试用、预付费、异常请求或预计费用可能超过 1 元，立即停止并回滚。

## 两阶段部署顺序

1. 阶段一：IaC 只创建安全组、RDS 5432 出站规则、两个禁用调用的函数和两个并发限制，
   共 6 个资源；此时没有公网触发器，无法被 ChatGPT 或 Codex 调用。
2. 代码上传：使用 Function Compute 官方 GetFunction 获取当前 ETag，再以 `If-Match`
   条件调用 UpdateFunction，把已验证的 15.6 MB ZIP 分别上传到两个函数；请求同时提交
   与 Go `hash/crc64.MakeTable(crc64.ECMA)` 一致的 CRC-64 值
   `17688003829125096702`，不改环境变量、网络、权限或现有插件。
3. 阶段二：确认两个云端 `codeChecksum` 都等于本地 CRC-64、`codeSize` 都等于
   15,581,274、`lastUpdateStatus=Successful`，且调用仍被禁用后，在同一 IaC state 中解除调用限制并新增
   两个版本、两个别名和两个 JWT HTTP 触发器，最终仍为 12 个受管资源。
4. 验收：仅执行未授权拒绝、初始化、工具清单和只读数据库查询，随后按回滚流程清理。

## 回滚

- 所有新增基础设施保存在独立 IaC 远程状态中。
- 测试结束或失败时销毁本次创建的两个函数、两个版本、两个别名、两个触发器、
  两个函数并发配额、一个 Advanced Security Group 和一条出站规则，共 12 个受管资源。
- 现有 RDS、VPC、VSwitch、插件、应用映射和隧道不在状态中，不可销毁。

  域名部署不在本次不超过 1 元的授权范围内。

  无法通过下载/解包校验。改为“小型占位包 IaC 创建 → UpdateFunction API 上传真实
  包 → 同一 state 发布版本和入口”的两阶段部署；不增加云资源，也不改变费用上限。
- 2026-08-22：由于 Terraform 对真实代码使用 `ignore_changes`，发布前增加独立云端
  证明门：GetFunction ETag 条件更新、CRC-64/ECMA、文件大小、成功状态和调用禁用状态
  必须全部匹配，验证记录写入任务目录后才能进入阶段二。
