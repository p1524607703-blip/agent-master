# 鞋类 Alexa 问题模板 v4 审核稿

> 状态：已审核并写入 `footwear-v4.0.0` 正式问题集；本文保留为设计审计记录。

## 一、统一规则

1. 每个独立新会话问题都必须重新写明 `{audience}` 和 `{product_type}`，不能依赖上一轮或当前页面替用户补全品类。
2. 独立对照题不出现品牌、ASIN、“历史品牌”“此前浏览”“上下文污染”等提示语。
3. 请求全部候选时使用简短的一行式输出，避免因解释过长导致回答中途截断。
4. 不做固定 Top 5；记录 Alexa 本轮实际返回的全部候选、自然顺序和全部商品链接。
5. 页面事实、评论证据和 Alexa 推断必须分开；无法确认就写“未知”，不得补猜。
6. 插件从商品卡片 DOM 独立提取链接；Alexa 正文中的裸 URL 不直接算有效链接。
7. Alexa 给出的推荐指数属于被测模型自述，只作诊断；主推荐指数继续由版本化代码规则计算。
8. 递进组允许测试页面锚定和上下文变化，但不进入主推荐指数。

## 二、动态占位符

- `{audience}`：受众，例如“女士”
- `{product_type}`：严格商品类型，例如“足弓支撑人字拖”
- `{inverse_product_type}`：冲突鞋类，例如“封闭式运动鞋”
- `{primary_function}`：页面证明的主要功能，例如“足弓支撑”
- `{implicit_primary_need}`：自然语言需求，例如“走久后足弓容易疲劳”
- `{scene}`：页面证明的使用场景，例如“夏季日常步行”
- `{capability_requirement}`：页面证明的能力，例如“湿地防滑”
- `{material}`：页面证明的材质或结构，例如“一体式 EVA”
- `{current_page_product}`：当前页面商品，只能在递进诊断组中引用，不得写入独立对照题
- `{budget_ceiling}`：运行前按标准价格带锁定的预算上限，例如“15美元以内”；不能根据 Alexa 当轮结果临时改写

## 三、独立新会话对照组（最多 5 题）

### F1 品类自然基线

角色：`baseline`，不计主分。

```text
我想购买适合{audience}日常穿着的{product_type}。请列出本轮实际建议我了解的全部候选，不要只做Top5。按自然推荐顺序，每个商品只写一行：商品名｜当前价格｜Amazon商品链接。候选池规模或价格无法确认时，请直接写“无法确认”。
```

观察：完整候选数、自然顺序、目标商品是否自然出现、有效链接数。

### F2 主要功能直接表达

角色：`positive_control`；页面证据对齐时可进入主指数。

```text
我只考虑{audience}{product_type}，需要明确具备{primary_function}。请列出本轮实际符合条件的全部候选，不要只做Top5。每项只写一行：商品名｜支持该功能的公开证据｜主要限制｜当前价格｜Amazon商品链接。无法验证的功能不要推断。
```

观察：目标商品进入率、顺序、功能证据归属、类别漂移。

### F3 自然语言需求表达

角色：`positive_control`；页面证据对齐时可进入主指数。

```text
{implicit_primary_need}。我只考虑{audience}{product_type}，并且需要适合日常较长时间穿着。请列出本轮实际建议的全部候选，不要只做Top5。每项只写一行：商品名｜为什么适合这个实际需求｜主要不确定性｜当前价格｜Amazon商品链接。
```

观察：Alexa 能否把自然需求映射到主要功能，同时保持严格鞋类。

### F4 公开证据比较

角色：`positive_control/comparison`；页面证据对齐时可进入主指数。

```text
请比较本轮最相关的全部{audience}{product_type}在{primary_function}方面的表现，不要只做Top5。按你认为的自然优先顺序，每项只写一行：商品名｜相对优势｜相对限制｜公开商品证据｜Amazon商品链接。请把页面事实、评论信息和你的推断分开；证据不足时写“未知”。
```

观察：目标商品比较资格、相对顺序、证据质量、链接真实性。

### F5 负向品类对照

角色：`negative_control`，不计主分。

```text
我只考虑{audience}{inverse_product_type}，明确排除任何{product_type}。请列出本轮实际建议的全部候选，每项只写商品名和Amazon商品链接。
```

观察：目标商品及其 ASIN 别名是否被正确排除；若进入则记为类别冲突。

## 四、单会话递进组（固定顺序，最多 6 题）

### P1 建立自然候选集

```text
我想购买适合{audience}日常穿着的{product_type}。先列出你本轮实际建议我了解的全部候选，不要只做Top5。按自然推荐顺序，每项只写一行：商品名｜当前价格｜Amazon商品链接。
```

保存：初始候选、顺序、链接和目标商品是否出现。

### P2 获取 Alexa 自定义推荐指数

```text
针对上一轮全部候选，并把{current_page_product}作为一个普通对照项，请先说明你会从哪些维度判断推荐程度，最多6个维度，并让权重合计100。然后按同一套标准给每个候选一个0到100的推荐指数。每个维度直接给0到该维度权重的加权分，总分只能由各维度分数相加，不要再次乘权重。请区分页面事实、评论证据和推断；没有证据的维度标记“未知”，不要编造比例或样本量，也不要因为它是当前页面商品而优先。
```

用途：观察 Alexa 自己声明的推荐标准、我方商品与自然候选的原始自评分，不计主指数。

### P3 候选池与筛选透明度

```text
这些候选是怎样进入本轮推荐的？请分别说明你实际能够确认的候选数量、使用了哪些可见信息、哪些筛选过程无法确认。不要估算Amazon全站商品总量，也不要把评分、销量、广告或历史行为说成确定的内部排序规则。
```

用途：检测候选池夸大、内部机制臆测和数据来源混淆。

### P4 无品牌进入条件与查询建议

```text
假设用户第一次咨询这个品类，并且不使用品牌词或ASIN。根据{current_page_product}当前可核验的商品事实，哪些真实需求、使用场景、预算条件和属性组合会使它有资格成为合理候选？请生成最多3条自然用户问法，并为每条标出所依据的页面证据。不要声称这些词一定会提高Amazon内部排序；它们只是下一步需要用新会话验证的测试假设。
```

用途：生成无品牌、无ASIN的需求词和提示词广告测试假设。Hermes 必须在日志中保存建议问法、证据ID和生成理由；这些建议本身不计分，只有后续新会话的实际结果才能验证。

### P5 场景收窄

```text
如果需求进一步限定为适合{scene}的{audience}{product_type}，你本轮会推荐哪些商品？不要只做Top5。每项只写一行：商品名｜进入理由｜替换条件｜当前价格｜Amazon商品链接。请标出相对第一轮新增、保留和退出的商品；只陈述可见证据，不推断Amazon内部权重。
```

用途：观察场景需求是否使当前页面商品自然进入、保留或退出，并记录与初始候选的差异。

### P6 预算收窄与复评分

```text
在保留{scene}和{primary_function}要求的前提下，把预算进一步限制为{budget_ceiling}。请重新列出本轮全部候选，并沿用P2的同一评分标准复评分。每项只写一行：商品名｜推荐指数｜进入或退出原因｜已知风险｜当前价格｜Amazon商品链接。请特别标出{current_page_product}是新增、保留还是退出；不要因为低价自动优先，也不要把历史偏好或内部排序当作已知事实。
```

用途：验证“场景 + 低价”是否是当前页面商品的实际进入条件，并观察价格约束前后的分数与候选变化；不替代代码主指数。

## 五、三个运行预设

### 冒烟：3 + 2

- 独立：F1、F2、F5
- 递进：P1、P2
- 目的：验证会话、候选提取、链接和评分格式是否可用

### 校准：5 + 4

- 独立：F1—F5
- 递进：P1—P4
- 目的：验证自然/直接表达、比较、负控制、Alexa 自定义评分和上下文反事实

### 完整：5 + 6

- 独立：F1—F5
- 递进：P1—P6
- 目的：获得完整候选轨迹、当前页面商品诊断分、无品牌进入条件、场景变化和预算敏感性

## 六、计分边界

- 主推荐指数：只使用 F2、F3、F4 中满足“新会话、页面证据对齐、有效卖家页面证据、完成状态”的轮次，由代码计算。
- F1：自然基线，只报告。
- F5：负控制，只报告正确排除率。
- P1—P6：上下文与提示工程诊断，只报告候选变化、Alexa 自评分、证据覆盖和一致性。
- Alexa 自称的推荐指数、候选池规模和内部原因均不能直接当作 Amazon 官方排序规则。

## 七、与 v3 的主要差异

1. 所有独立问题重复严格品类，避免场景题漂移到运动鞋或普通凉鞋。
2. 不在独立题里写“忽略历史/此前品牌”，避免反向触发账户记忆。
3. 递进组从机械条件增删改为更贴近真实用户的“推荐—评分—追问来源—无品牌进入条件—场景收窄—预算收窄与复评分”。
4. 加入明确的加权分算术规则，防止 Alexa 再次二次乘权或合计错误。
5. 请求简洁的一行式全体候选，降低“不做Top5”造成输出截断的概率。

## 八、Hermes / DeepSeek 可建议的问题方向

以下问题可由模型根据当前页面事实提出，但不能自动追加到 5+6 上限之外。开发者可在审核页选择用建议题替换 P4—P6 中不适用的一题：

1. **价格带进入条件**：不使用品牌词时，什么预算区间和需求组合最贴合当前页面商品？
2. **使用场景进入条件**：海边、泳池、浴室、日常步行、旅行等场景中，哪些有页面证据支持？
3. **材料与结构进入条件**：例如轻量、防水、快干、一体式EVA、防滑纹理，但必须绑定页面证据ID。
4. **风险反证**：如果存在高温缩水、尺码、耐久或湿地防滑风险，哪些需求会使该商品不再合适？
5. **自然用户问法**：基于一个需求组合生成最多3条不含品牌和ASIN的自然问句，供后续独立新会话实际验证。

AI 建议题必须同时保存：建议题文、引用的页面证据ID、适用模板槽位、替换理由，以及“不得解释为Amazon内部排名规则”的诊断标签。
