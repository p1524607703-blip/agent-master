# Alexa 首页盲控测试报告

- 测试日期：2026-07-17
- 测试入口：Amazon 首页 Alexa
- 浏览器：Safari
- 测试方式：5 个独立新会话；不打开目标商品页；问题中不主动提供 Joomra 名称或 ASIN
- 链接核验：只把当前 `#rufus-react-renderer` 内真实 `<a href>` 计为可点击链接；正文里的裸 URL 或“查看商品”文本不计
- 页面读取：忽略 `#rufus-status-announcer` 中的旧会话残留，只读取当前活动渲染容器

## 结论

1. 回到 Amazon 首页并点击“New chat”不能消除账户级上下文。第五轮重试中，Alexa 明确写出：“您的账户备注显示您曾要求降低该品牌权重”，并据此主动剔除 Joomra。
2. “不要使用历史/不要复述此前品牌”这类负向提示词反而会触发模型检查或复述历史。第二、第四轮都在用户未输入品牌名的情况下主动提到 Joomra。
3. 自然基线反而没有出现 Joomra：第一轮列出 20 个候选，Joomra 未入选。说明测试提示词本身可能改变记忆调用路径，不能把“抗污染提示组”直接当成自然用户组。
4. Alexa 无法稳定返回“全部候选”。第二轮声称完整列出，但在第 21 项中途被截断；第四轮在第 8 项中途被截断。
5. “可点击链接”要求没有被稳定执行。多数 Amazon 商品卡在活动 DOM 内没有真实锚点；模型只在正文中写裸 URL 或不可点击文本。真实锚点主要出现在“Available from the Web”卡片。
6. 独立会话必须在每道题里重复商品类别。第三轮只写场景和预算，没有重复“女士足弓支撑人字拖”，Alexa 随即把 6 双封闭式步行鞋纳入结果。
7. Alexa 会同时给出“页面事实”“评论证据”和推断性结论，但来源边界仍不可靠。任何评分、比例、医疗级别或耐久结论都不能直接作为确定性计分输入。

## 对现有提示词的修正

不再把以下文字放进 Alexa 用户提示：

- “不要使用此前历史”
- “不要复述此前品牌”
- “若受账户历史影响请说明”

这些措辞会把“历史/品牌”变成显著注意线索，可能主动触发记忆检索。真正的盲控应由测试环境隔离完成，而不是要求被测模型自我隔离。

建议的自然用户基线提示：

> 我想买女士足弓支撑人字拖，主要用于日常步行和夏季出行。请列出你本轮实际建议我了解的全部商品，按自然推荐顺序说明入选理由、主要限制、当前价格和 Amazon 商品链接。无法确认的内容请直接写无法确认。

建议的严格类别提示：

> 我只考虑女士足弓支撑人字拖，不考虑运动鞋、休闲鞋、洞洞鞋、普通拖鞋或非人字结构凉鞋。预算不超过 20 美元，重点是足弓支撑、舒适、防滑和夏季步行。请列出本轮实际符合条件的全部候选，并说明证据、限制、价格和 Amazon 商品链接。

## 下一轮实验设计

采用环境对照，而不是提示词对照：

1. A 组：未登录或全新专用测试账户、全新浏览器配置、Amazon 首页。
2. B 组：当前已登录账户、Amazon 首页、New chat。
3. C 组：当前账户先浏览目标商品页，再回首页、New chat。
4. 三组使用完全相同的自然提示词，不出现“历史、此前品牌、上下文污染”等字样。
5. 每组至少重复 3 次，记录目标商品是否出现、自然顺序、是否有真实链接、候选数和输出错误。

这样才能区分：自然检索波动、账户级个性化、商品页上下文和提示词诱导四种因素。
