# 亚马逊多账户产品日级 CPO 自动整理 SOP

当前基线版本：**V3.4**

## 简介

本 SOP 用于把多个 Seller Central 业务报告、多个 Amazon Ads《推广的商品》报告与运营 SKU 主表合并为“产品 × 日期”粒度的日度 CPO 记录。

它重点解决多账户、多运营、同款异性别、跨广告账户和混合 Campaign 等场景中的归属问题，目标是减少人工抄表、避免跨运营串数，并让每笔费用与广告单量可以追溯、校验和复用。

## 核心输入

- 《运营 SKU 产品表》：确定“哪位运营的哪一款”，建立 ASIN/SKU 白名单。
- Seller Central 业务报告：提供父 ASIN、全部订单、Sessions 与 CVR。
- Amazon Ads《推广的商品》报告：提供广告费用、广告单量及 Campaign 明细。
- 《Campaign 归属规则表》（可选但建议固定维护）：保存已确认的特殊 Campaign 口径。
- 历史 CPO 模板（可选）：保持既有字段结构与顺序。

> 原始业务报告、广告报告、SKU 明细及凭据不上传到本目录。

## V3.4 主流程

1. 多运营共享账户先加载《运营 SKU 产品表》；缺表时停止产品级计算。
2. 确认本次运营身份，并映射到具体小组。
3. 使用“运营小组 + 款式”建立内部产品主键，禁止同款不同运营自动合并。
4. 自动识别目标日期、业务账户、广告账户和父 ASIN。
5. 在正式计算前强制回显“运营 / 产品代号 / 业务账户 / 广告账户 / 父 ASIN”五列映射表。
6. 广告数据先做运营隔离，再执行产品归属和 Campaign 特殊规则。
7. 对普通、历史 ASIN 口径、混合 Campaign 和人工确认规则分别处理。
8. 执行费用、广告单、产品身份、账户完整性及跨运营串数校验。
9. 输出“一款产品、一个日期、一行”的 CPO CSV，并主动反馈异常与分摊说明。

## 核心规则

- 内部产品主键：`运营小组|款式`。
- SKU 表负责产品身份，不负责当天业务数值。
- 业务报告负责销量、Sessions 和 CVR。
- 广告报告负责费用与广告归因数据。
- Campaign 规则表只记录默认规则容易算错、且已由运营确认的特殊活动。
- 普通 Campaign 默认按 Campaign 产品代号归属。
- 历史推广商品口径可按推广父 ASIN / ASIN / SKU 逐行归属。
- 混合 Campaign 在有商品明细时精确拆分；无商品明细时按已确认白名单等分。
- `AUTO / 自动` 的分类优先级高于“广泛 / 词组 / 精准”等命名词。
- 未完成五列映射回显或发现跨运营数据混入时，不输出最终 CPO。

## 输出

V3.4 输出包括：

- 产品与日期；
- 手动、自动、头条、视频、展示的费用；
- 各广告类型单量及平均费用/单；
- 总费用、总广告单、全部订单与整体 CPO；
- Sessions、CVR；
- 必要的流媒体独立记录与异常说明。

流媒体正式并入六分类结构、广告单量字段口径等已完成业务复盘，列入下一版本待发布项，详见 [CHANGELOG.md](./CHANGELOG.md)。
