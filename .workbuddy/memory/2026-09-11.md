## 业务报告管线：首周体检 + 修了一个静默缺口

用户问「每日业务报告最近几天跑得怎样、数据库时间窗口多少」。

**结论 1：业务报告数据没进 RDS。** br_pull.js 只落本地 CSV，脚本无任何入库逻辑。
RDS 连接靠 PGPASSWORD 环境变量，代码里没有、也无 ~/.pgpass → 想查库必须先要密码。

**结论 2：本地 CSV 覆盖 2026-09-06 ~ 09-09（两店各 4 天）**，09-10 还没到跑的时间
（北京 9/12 09:00 = 本机 9/11 21:00 才会导出 9/10）。

**事故：9/10 21:00 那次进程跑一半被杀**——川鹏 09-09 出了，欧德思没出，
且 `logs/` 里**连日志都没有**（flushLog 只在 main 结尾调用，进程死了就全丢），
缺口静默存在 3 天才被发现。已手动补跑欧德思 09-09（28 行）。

**两处加固（br_pull.js）**
1. `flushLog()` 改为**每跑完一店就落盘**，进程被杀也能留下已跑部分
2. 新增**自动补洞**：每次运行扫描最近 3 天（`--backfill N` 可调、`--no-backfill` 关），
   对「店铺 × 日期」缺失组合自动补跑，job 带 `only` 字段做单店定向。
   实测 `--backfill 8` 能正确列出 09-03~09-05 的历史缺口

**新增认知（别踩）**
- **不要在太平洋凌晨手动跑当天**：现在跑会导出「昨天」，而定时任务（北京 9:00 =
  太平洋 18:00）当天也会导出同一天，但文件已存在会被幂等跳过 → 凌晨那份不完整数据
  会永久留下来。手动补跑请显式指定 `--from/--to` 历史日期。
- 用户问「数据库时间窗口」时，先确认这批数据到底有没有入库，别默认已入。

## 业务报告已入 RDS（用户给了密码，要求导入）

**连接真相**：`amazon_ads_admin` + Root1234 **连不上**（密码不对）；
**`postgres` + Root1234 可以**。已写入标准 `~/.pgpass`（chmod 600），psql 免密。

**不需要建表** —— 库里早就有 `core.business_report_parent_asin_period`（owner amazon_ads_admin），
16 个指标列与 CSV **完全对齐**，唯一键 `(account_id, report_start_date, report_end_date, parent_asin)`。
表名 period = 按期间存储：单日存 (D,D)、周快照存 (周一,周日)，靠 start/end 区分互不覆盖。
存量：WHITIN 7/17~8/26、BLOOMNEXT 7/17~8/25、JOOMRA DIRECT 8/26。

- 欧德思美站 → BLOOMNEXT → `amzn1.ads-account.g.dfa7o7cwdl371d634ew58i919`

**脚本** `business-report/br_to_rds.py`（psql COPY，无 psycopg2 依赖）。
**结果：8 个文件全导入，9/6~9/9 两店共 683 行**，川鹏日销 17~22 万美元 / 会话 12~13 万，
欧德思日销约 5 万 / 会话 2.7~3.1 万。

**调试踩的 5 个坑（写 psql 脚本必看）**
1. `-tAc` 里的 `c` 会被当成 `-c` 选项吞掉后面的参数 → 必须分开写 `-t -A` + `-c`
2. psql 位置参数是 dbname，SQL 必须用 `-c` / `-f` 传
3. **`-c` 模式下 `:variable` 插值不生效** → 只能在 Python 侧转义拼字面量
4. `RETURNING` 返回时 stdout 会附带 `INSERT 0 1` 命令标签 → 取第一行
5. `\copy FROM STDIN` 在 `-f` 脚本模式下终止符易出错 → 改落临时 CSV + `\copy FROM '路径'`
6. f-string 里写 `''` 会被吞成空参数 → 抽成函数用双引号包裹
