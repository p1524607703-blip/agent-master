## 川鹏广告费用分摊 新旧算法「人话翻译」

读了用户桌面的 `川鹏_AMS及站内广告费用分摊_SOP_V1.7.2_执行口径锁定版_2026-09-17.md`（887 行，23 章，全是「不得」）与 `川鹏广告费用分摊新旧算法说明.md`，输出吐槽风格的口径翻译 + 新旧流程对比图。

要点沉淀（**这套规则与「CPO 分摊」是两条线：CPO 是广告费 ÷ 业务销售额，这份 SOP 是广告费在运营小组之间的再分配**）：

- 旧算法 = `Campaign 总花费 ÷ 总归因件数 = 平均单件成本`，再按各产品归因件数直接分；跨组分摊**有封顶**（不能超原始花费），创建组承担剩余
- 新算法 = 先查户口（Campaign ID → 实际推广商品 → 成交 ASIN/SKU → 产品款式 → 运营小组，100% 唯一映射），再算**产品正常广告成本**（自己广告归因 ≥10 件才有效），按 `≤0.5×` / `≥2×` 判高低并修正单价（低 → 正常成本 ×0.8；高 → 正常成本 ×1.25；正常区间用原始平均成本），**取消跨组封顶**，允许创建组负承担（形成费用抵扣），但账户总费用不变、逐 Campaign 平账
- 广告范围扩到全类型：SP + SB/SBV + SD + STV，只要当月有真实花费就进费用池；**Campaign ID 是唯一主键**，同 ID 只算一次（防 SB/SBV 双标签重复计费）
- 跨账户归因不对称专项保护：欧德思 XM1/XM2、洁博利 AJ。**只有当月在该来源实际投放过**才允许承接该来源 Halo；AMS 与川鹏站内资格独立、不能互借；未通过资格的 Halo 保留原始归因但不参与分摊，费用回到创建组
- 同小组不同款 Halo：保留归因、不做组间转移、不做 0.5/2 倍修正
- 有花费 0 归因 → 100% 创建组承担；有归因无花费 → 不进分摊、不反推成本
- 映射可复用、**金额必须全量重算**；证据不足且影响金额 → 停止交付不猜
- Excel 交付固定 8 页签 + 版式全保，不得加技术页/调试页

## 续：三档修正算例 + 用户理解校准

- 用户要求把 `≤0.5× → 0.8n；≥2× → 1.25n；中间 → c` 讲细。给了三档完整算例（n=$10、C 归因 500 件其中目标产品占 200 件）：
  - c=$2 → 单价 $8 → 目标组 $1,600 / 创建组 **-$600**
  - c=$6 → 单价 $6 → $1,200 / $1,800
  - c=$25 → 单价 $12.50 → $2,500 / $10,000
  - 三档均满足 `总花费 = 创建组 + 其他组`
- 澄清三个易错点：① 修正落点仍偏离正常成本（0.8n / 1.25n，不是拉到 n），设计是"往正常价靠一步"；② 阈值**闭区间**，正好 0.5n / 2n 触发修正；③ **只改单价不改件数**
- 明确修正的**四条排除项**：同组不同款 Halo / Campaign 实际直接推广的其他组产品 / 目标产品自己归因 <10 件 / 有花费 0 归因 → 一律不执行修正
- 用户随后两次要求"再简单一点"，最终收敛为一句：**别人帮你卖的单，不按他的广告实际成本算，按你自己打广告的正常单价折算**
- **用户提出并被确认的关键前提**：每月必须把成本算清楚。补充两点：要算的是**两套**成本（每个 Campaign 的 `c` + 每个产品的 `n`）；且 `n` 的分子分母必须先完成归因三分类才能筛出 → **先分类、后算基准**；`n` 是 AMS + 川鹏站内**合并一套**基准
- 沉淀到 `PLAYBOOK §N`（N.1 旧新对比 / N.2 三档公式与算例 / N.3 四条排除项 / N.4 专项保护 / N.5 硬约束 / N.6 两套成本与执行顺序）

### 🔴 P0 事实表重复导入（最严重，非映射表问题）
`川鹏_*` 与 `AMS_*` 两份源文件装的是**同一账户 anac1973 (C3S8S)** 数据，日期错开一天几乎全重叠，被双份入库：
| 表 | 现状 | 去重后 | 虚增 |
|---|---|---|---|
| 广告活动 | $131,641.92 | 同 | 0% ✅（两份不重叠，侥幸干净）|
| 推广的商品 | $254,462.00 | $129,959.64 | +95.8% |
| 达成转化的商品 | 37,687 件 | 19,350 件 | **+94.9%** |

机制：同 Campaign-日两行，仅 `advertised_product_id` 不同（`''` vs `__advertised__<hash>` 占位符）→ 去重键没覆盖。实例 campaign `137718483524592 XM2-S71 头条wide广泛`。
**致命原因**：SOP 单价 = 花费 ÷ 归因件数；件数翻倍 → 单价腰斩 → 大面积误触低成本修正 → 全链错。**仅 anac1973 一个账户受影响**（BLOOMNEXT/JOOMRA 零重复）。
修法：去重键加 `account_scope` 并归一 `__advertised__*` 占位符。
