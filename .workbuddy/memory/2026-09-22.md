### 概念结论（供复用）

- **CC Switch**：改**配置文件**层（`~/.claude/settings.json`、`~/.codex/config.toml`+`auth.json`、`~/.gemini/.env`）做多供应商切换；可选启**本地反向代理**（127.0.0.1:15721）实现故障转移/重试/断路器/成本记账。Claude 热生效，**Codex 必须重开终端**。跨 Claude/Codex/Gemini/OpenCode/OpenClaw。
- **Codex++**（作者 BigPizzaV3，站点 codexplusplus.com）：Rust 核心 + Tauri 面板，**外部 launcher + CDP(9222) 向 Codex App 渲染进程注入 `renderer-inject.js`**，本地 HTTP 回调 18451。零文件修改、官方更新不失效。只对 **Codex 桌面 App** 生效，对 Codex CLI 无效。能力 = 中转注入 + 增强菜单 + 会话管理/ SQLite 备份与回滚 + Timeline + 用户脚本。
- 一句话区分：**CC Switch 换的是「配置」；Codex++ 改的是「客户端内部行为」。** 二者不冲突、可共存。
- **中转代理性质**：远程中转站 = 形态上是**反向代理**（客户端只认一个入口、上游拓扑被隐藏）+ 商业本质是**凭据套利/算力转售**（运营方持有自己的官方 Key 或 ChatGPT 订阅号池，TLS 在它处终止 → 能看明文 prompt，可做模型降级/注入 system prompt/并发串号 = "降智""提示词脏"）。号池逆向网页端（PoW + Turnstile + JA3/JA4 指纹伪装）那一类更准确叫**逆向网关**，已不算标准反代。CC Switch 本地代理 = **本机回环反代**（可审计）。Codex++ CDP 注入 = **不是网络代理**。
- **Codex 接中转的最小配置**：`model_provider` 指向 `[model_providers.xxx]`，字段只能写 `name`/`base_url`/`env_key`/`wire_api` 四个（多写报错）；`wire_api="responses"`（新版默认，只支持 chat completions 的模型才写 `"chat"`）；`base_url` 写到 `/v1` 为止别带 `/v1/responses`；`openai`/`ollama`/`lmstudio`/`amazon-bedrock` 是保留名；配 `requires_openai_auth=false` + `disable_response_storage=true` + `preferred_auth_method="apikey"`。
- ⚠️ 风险提示已给出：违反上游 ToS（封号属预期内）、明文数据过手、运营端涉非法经营。用户为 Amazon 卖家（数据敏感），已强调不要把敏感素材走不明中转。

## 追问深化：中转代理的「上下文记忆」问题（含本地实证）

### 问题本质

上下文有两条存放路径，中转都会打断：

1. **服务端有状态**（OpenAI Responses 的 `store` + `previous_response_id`）：官方存历史，后续只发 delta。中转站 key 池轮换 → ID 落到别的账号 → 查不到 → 400 或静默失忆。故接中转必须 `disable_response_storage = true` 改走客户端全量重发。
2. **前缀缓存**（`cache_control` / prompt caching）：全量重发想便宜全靠它。中转会弄失效的三种方式：① 剥掉/丢弃 `cache_control` 标记（或把 block-form system 转成纯字符串）→ 整段历史按未缓存计费；② 注入 system prompt 或 Claude Code 2.1.36+ 的**随机归因头**（官方忽略此字段、第三方不忽略）→ cache key 每轮都变；③ 上游账号漂移 → 缓存按账号/组织隔离，池子轮换即全 miss。

官方文档佐证（claude.com/docs/en/prompt-caching）：cache 读写比 = 未命中价 vs 读价 1/10（Anthropic 读 0.1x、写 1.25x）；会失效缓存的动作含换模型、换 effort、开关 MCP/plugin、compact、改 system prompt、增删工具定义。另 Anthropic 实测：把**每请求变化的文本**（时间戳/队列位次）放在稳定前缀前面，25 token 的状态行能把整轮成本从 $0.59 推到 $4.24。

### 本地实证（`~/.cc-switch/cc-switch.db`，2026-09-22 采集）

`proxy_request_logs` 中 codex 共 **14,673** 条（全部 `data_source='codex_session'`，`input_token_semantics=0`），时间跨度 2026-05-19 → 2026-09-22，6 个模型：

| 指标 | 值 |
|---|---|
| input 合计 | **2,102,492,485**（21.02 亿） |
| output 合计 | 6,391,626（639 万） |
| **input:output** | **约 329:1**（健康值应 <20:1） |
| cache_read 合计 | **2,007,514,112**（20.08 亿）＝ input 的 **95.5%** |
| cache_creation | **恒为 0**（OpenAI 自动缓存不区分写计费） |
| input 平均 / 最大 | **143,290 / 272,482** |
| input >100k 的条数 | **11,023 条（75.1%）** |
| 单次成本量级 | ≈ $0.0018 |

会话文件佐证：最新 rollout `~/.codex/sessions/2026/09/22/rollout-2026-09-22T03-13-41-*.jsonl` 中 **`previous_response_id` 出现 0 次**，只有 8 处 `response_id`（响应侧）→ **Codex 当前是客户端全量重发（stateless）**，靠 95.5% 前缀缓存维持低成本。

⇒ **结论：现状 = 全量重发 + 高缓存命中，是经济的组合。换中转站的真实风险不是"失忆"，而是把 95.5% 的缓存命中打到 0，同样 14 万 input 变成全价重算，输入成本量级可涨约一个数量级。** 选中转前必须先验缓存是否透传。

### 附带发现：会话索引缺失

`~/.codex/session_index.jsonl` 仅 **67** 行，而 `sessions/` 下有 **119** 个 rollout 文件（`archived_sessions/` 另 3 个）→ **至少 52 个会话没进索引**。症状 = 会话列表里看不到，但文件还在（`codex resume <session_id>` 能拉起）。这是换 provider 后 Index 未回填的典型表现，**不是数据丢失，别删配置文件重装**。

### 关键路径速查

- 会话原始文件：`~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`
- 会话索引：`~/.codex/session_index.jsonl`（会缺）｜线程状态：`~/.codex/state_5.sqlite`
- 用量账本：`~/.cc-switch/cc-switch.db` → `proxy_request_logs` / `usage_daily_rollups`
- 排查 `previous_response_id`：`grep -c previous_response_id <rollout>`；为 0 → 走客户端全量重发

### 选型体检清单（可复用）

1. 价格锚：**低于官方价就是在补贴** → 补贴的钱从哪来（黑卡/免费额度套利/降级混模）？

5. 是否注入 system prompt / 静默降级模型 / 重写工具定义。

7. 计费透明度：能否导出逐条请求明细（含 cache read/write 字段）、能否开票。
8. 售后形态：有工单/公司主体/对公账户 = 相对可信；只有微信群和电商链接 = 准备跑路。
9. 稳定性冗余：别把关键链路押在单一供应商；配多 provider + 故障转移。
10. 🔴 数据红线：Amazon 卖家凭据、客户信息、未脱敏业务数据**不要过不明中转**。

## 「外包团队共享 2 个 20x + 日本自建中转 + Codex++ 启动」套路解析（2026-09-22）

### 名词解码

- **20x 账号 = ChatGPT Pro 20x（$200/月）**，额度 = Plus 的 20 倍。Pro 现分 **Pro 5x（$100/月，2026-04-09 新增）** 与 **Pro 20x（$200，原 Pro 重新定位）**；两者 Codex 配额上限据说相同（均约 10× Plus），差别在整体使用额度。
- 🔴 **致命时效：2026-09-10 起 Pro 20x（$200）对新买家关闭**（暂停新注册与升级，含自 Free / Go / Plus / Pro$100 升级），原因 = GPT-6 Astra（2026-09-03 发布）后的需求。现有 $200 订阅继续续费，Pro 5x 不受影响。⇒ **"共用两个 20x" 这个前提今天已不可复制**（除非账号是早就有）。
- **额度是共享池**：Codex CLI / IDE 扩展 / Codex cloud / ChatGPT Work / 桌面 App 共用一份 agentic usage + credit pool；本地消息与云对话同池。**Pro 上真正卡点是周限额**（5 小时滚动窗口 2026-07 移除，2026-08-25/26 仅对 Plus 恢复，Pro $100/$200 仍关闭）。
- **2026-04-02 起改 token-based credit 计费**（不再按消息数）。Credit 折算（输入 / **缓存输入** / 输出，每 1M token）：GPT-5.5 = 125 / **12.50** / 750；GPT-5.4 = 62.50 / **6.25** / 375；GPT-5.4-mini = 18.75 / 1.875 / 113；GPT-5.3-Codex = 43.75 / 4.375 / 350。
  → ⭐ **缓存输入恰为输入价的 1/10**，印证「缓存失效 = 额度按约 10 倍速烧」。订阅制下烧的是额度不是钱，但同样致命。

### 设计动因（每步在解决什么）

1. **日本服务器**：大陆直连 OpenAI 不通，需境外落地；日本延迟最低（交互式编码体验），且属 OpenAI 支持地区（香港不在支持列表）。
2. **自建而非买第三方中转**：凭证与数据留在自家手里，不会被降级/抽成/倒卖。**这是这段话里最聪明的一步**。
3. **Codex++ 启动而非原生 Codex**：原生 Codex App 在 API Key / 自定义端点模式下**插件入口变灰**（要求登录 ChatGPT）且无法既接自定义端点又保插件 → 用 Codex++ 的「中转注入」改端点 + 「插件解锁」恢复插件 + 「Provider 同步」保住会话列表。
4. **账号池必须做会话粘性（session affinity）**：否则同一会话轮换到另一账号 → 前缀缓存失效 + 撞上另一账号并发限额。

### 官方合规替代（对比结论）

- **Business**：**$20/用户/月**（年付，2+ 用户）或 $25 月付 → 独立工作区、SAML SSO、MFA、默认不用业务数据训练。**Enterprise**：无固定限额，共享 credit 池 + RBAC + Compliance API + 数据驻留控制。
- 性价比账：2×$200 = $400/月 换 40× Plus 等效额度（≈0.1 Plus/$）；Business 10 人 = $200/月 换 10× Plus（≈0.05 Plus/$）。**共享方案每美元额度约为 Business 的 2 倍**，代价 = 违反 ToS + 封号风险 + 无管理后台 + 额度竞争 + 数据出境。⇒ 不是"蠢"，是「用合规风险换 2 倍额度性价比」，值不值取决于对封号与数据出境的容忍度。
- 🔴 **比 ToS 更硬的风险**：外包公司的**客户代码经境外服务器 = 数据出境**，可能直接违反与客户的保密/数据处理条款。自建中转让数据留在自家手里，但"落地在境外"这一点不变。
