## 关键技术发现（已固化到 skill `ziniao-ad-change-history`）

1. **紫鸟 CDP 端口可直连**：`lsof -nP -iTCP -sTCP:LISTEN | grep ziniaobro` → 每个运行中的店铺一个端口。
   实测川鹏2号=39380、欧德思美站=35458。`curl http://127.0.0.1:<port>/json/list` 可枚举全部标签页（Bridge 本身只暴露活动标签页，看不到别的）。
2. **CDP target id == Bridge `--target-id`**：Bridge 只能操作活动标签页，但拿到 CDP 的 target id 后，
   可用 `ziniao-cli page exec --store-id X --target-id <cdp_id>` 精确操作任意标签页。这是本次的关键突破口。
3. **页面真实 URL 是 `/cm/history?entityId=...`**，不是用户口述的 `/bulk-operations`（左侧菜单叫「历史记录」）。
4. **数据走内部 API**：`POST /cm/api/event-history?entityId=...&method=history`，
   必须带 `X-CSRF-token` 头（不带 → 403 `Unauthorized request to campaign manager`；GET → 404 `Request method 'GET' not supported`）。
   token 获取：hook `window.fetch` 记录请求头抓取，或 GET `/ccx/ajax/advertisingApiCsrf`（后者格式不同，未必通用）。
5. **⚠️ 10,000 条硬截断**：`totalRecords` 到 10000、`maxPageNumber=50` 就停，且返回的是**最新**的 10000 条。
   全窗口查询 7/1–9/13 只能拿 10000 条；实际 19,150 条 → 直接损失 9,150 条（7 月数据几乎全丢）。
   **必须分片**：按 7 天切片，每片先查 totalRecords，≥9000 就二分细分。7 月单月即 >10000，8 月 5,846，9/1–9/13 2,971。
6. **`pageSize` 后端接受 10000**（不报错），分片后每片一次拿完。
7. 日期边界是**太平洋时间**（`fromDate=2026-07-01T00:00:00-07:00`），非 UTC、非北京。
8. 落盘方式：页面内 Blob + `a[download]` 触发下载 → 落到店铺 `downloadFolderPath`
   （`.../ziniaobrowserdatas/ziniao browser/川鹏2号`），不受 Bridge 返回值大小限制。8.6MB 数据一次搞定。
