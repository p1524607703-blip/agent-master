# 控制台模块精简与角色边界

管理层使用经营查询与业务审批，超级管理员在同一经营能力基础上承担系统维护。角色继承保留，系统管理入口与权限单独授予超级管理员。

| 角色 | 左侧入口 |
| --- | --- |
| 运营 | 我的 CPO 明细、运营共用汇总、广告费用分摊 |
| 管理层 | CPO 单双数据情况、广告费用分摊、产品映射 |
| 超级管理员 | 上述管理层三项，以及数据维护、人员与设备、系统诊断 |

## 删除和合并

- 删除待确认异常、规则管理：两者使用演示常量；原确认按钮仅修改浏览器内存，没有真实审批或保存能力。
- 删除旧广告投放概览：页面使用旧的单账户聚合口径且定时刷新；统一使用现行 CPO 页面。移除旧概览与趋势聚合、旧运营汇总实现、演示接口和数据常量。
- 删除早已下架的产品明细、广告类型页面及其专用组件。其旧入口和所有未知地址回到当前角色首页。
- 报告管理与 CPO 处理中心合并为“数据维护”，内设“报告覆盖”和“手动补传”。仅加载所选面板，保留真实手动补传能力，移除不能操作的“开始 CPO 计算”按钮。
- 映射提交与审批保留，通过费用分摊页进入；不再占用独立侧栏入口。
- 删除侧栏拖动排序和旧布局缓存读取，角色菜单直接从当前会话生成，旧缓存不能恢复已移除项目。

## 后端权限和性能

人员设备管理、额度历史、接入设置、诊断、缓存状态、健康检查、报表覆盖、手动补传状态及导入均要求超级管理员。管理层继续查询公司 CPO、查看产品映射和处理分摊及映射申请。设备心跳、模型代理继续使用原设备凭据鉴权。

已移除接口仅向已登录客户端返回 HTTP 410，不执行加载器或事实表查询。保留的报表覆盖读取持久化快照，后台维护流程继续运行。此改动减少入口、旧概览刷新和无用查询路径，不把代码行数减少当作实测 CPU 或数据库负载降幅。

原始广告事实、业务报告、已确认分摊结果、映射、用户角色记录、设备密钥及配置均无数据迁移或删除。

## 验收与发布

前端测试验证角色菜单、直达权限、旧书签回退与异步导航；后端测试验证管理层在数据加载前被拒绝、超管可读、业务查询保留及移除接口零业务读取。专用 PostgreSQL 和真实上游测试在没有隔离环境时跳过。另补齐原取消请求测试样本缺少的用户身份字段，以匹配当前遥测输入契约。

本地浏览器使用合成数据核对三项/六项菜单、管理层直达系统页回退、合并维护页及审批入口；合成数据不代表生产金额或业务覆盖情况。发布沿用 [[开发提交与上线流程]]，候选准备和正式激活分开。
