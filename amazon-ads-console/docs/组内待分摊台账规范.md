# 组内待分摊台账

默认 SB 命名口径区分两种未完成情况：运营也无法确认的费用，以及运营已确认但承担款式尚未确认的费用。后一种费用进入 `groupPendingExpenses` 独立台账，不生成虚构产品，也不按成交量或任意比例拆款。

## 进入条件

仅 `sb_attribution_mode=name` 生效。卖家账户范围必须已经确定；活动名称以唯一的精确运营组前缀开头；该组存在于同账户已维护的产品候选中。禁止绕过已批准活动规则复核、来源冲突或跨运营来源冲突。ASIN 模式继续依赖真实推广身份，Full-Funnel 无身份费用继续单独待分摊。

## 金额与接口

公司总费用 = 已落款产品费用 + 组内待分摊费用 + 运营未知费用 + 全流域待分摊费用。

运营总费用 = 本组产品费用 + 本组待分摊费用。广告单量和广告销售额同步桥接；业务订单、业务销售额、产品费用及实际 ASIN 不因台账而改变。台账是总费用中的子项，不能再次相加。涉及待分摊的运营综合 CPO/TACOS 留空，最终状态为待确认；产品已落款部分不冒充完整口径。

| 接口 | 新字段 |
| --- | --- |
| 管理汇总 | `operatorPendingSpend`、`groupPendingExpenses` |
| 汇总运营行 | `pendingProductSpend` |
| 单运营详情 | `groupPendingExpenses`、`summary.operatorPendingSpend` |
| 我的 CPO | `groupPendingExpenses`、`detailSummary.operatorPendingSpend` |

台账记录包含日期、广告账户、卖家范围、活动 ID/名称、运营组、费用、广告单量、广告销售额、原因和已识别款式候选。状态为 `GROUP_KNOWN_PRODUCT_PENDING`，不包含确定承担款的 `productCode`。

管理层可以查看全部台账；运营详情和本人接口仅返回本组台账。共享运营汇总保留原有费用可见范围，但不新增其他组的待分摊明细或 `pendingProductSpend` 字段可见性。

## 展示和导出

页面明确说明费用已包含在本组总费用中。个人 XLSX 综合行计入一次，产品行保持原值，另列独立台账连接两者。汇总 XLSX 和管理 ZIP 使用同一数据快照。台账中的单量为数字，费用和销售额为货币；空 CPO 保持为空。

确认承担款式需要有明确适用活动、有效期、候选款式和权重的财务规则。名称中的组合字符串、旧示例或其他活动的规则不能自动替代当前活动的确认。确认后应重新计算新版本，旧事实和历史冻结结果不被改写。

## 已确认的多款等分活动规则

仅 SB 命名模式可以使用 `multi_owner_equal`。规则记录精确账户、活动 ID、
完整活动名、业务账户、运营组、真实来源款白名单、生效起止日及审批证据；
`rule_config.targets` 为 2–20 个已维护的同组同账户款号及 Parent ASIN，权重均为 1。
旧单款规则与多款规则日期重叠、名称改变、出现新来源、目标失效时，整条活动
进入复查，不能只分配符合条件的部分。未审批的组合名称不会自动拆成款号。

按日期、账户、活动先合并真实推广明细，再分别等分费用、归因广告件数、
推广报告购买次数及广告销售额。公开精度为 0.01，以整数最小单位分配；
余数并列按运营组与标准款号稳定排序，保证输入总数与各目标合计相同。
审计保留原活动总数、来源款及分配权重。达成转化商品报告只用于独立核验，
其校验数量按同一已确认活动规则列示，不作为分配广告费用的比例依据。

已成功分配的金额移入真实款式，组内待分摊随之减少；组及公司总费用保持
守恒。业务订单和销售额不因费用承担款发生转移，实际推广/成交 ASIN 不改写。
汇总、详情、本人页面及 XLSX/ZIP 共用这一结果。ASIN 对照模式完全绕过命名规则。

多款规则的审批证据与受控生效记录应独立保存。当前商品映射上传页面并不等于
已经提供多款费用规则的自助提交/自动生效接口，不能仅将申请状态标为批准
就声称正式规则已生效。按单次明确授权受控写入时，也须记录修改前快照、
规则内容哈希、生效版本以及真实费用验收。
