# Codex 额度归属 rc.9：暂估批次与迟到计量回算

账户总额度为100%。人员已归属（本人确认、旧版结算、新版暂估）＋待归属＋官方剩余＝100%。具体 Token 独立计量；额度比例始终是估算，不是官方逐设备账单，也不能换算为订阅费用或套餐总 Token。

## 计量底账

每个子设备使用独立 Key，服务端根据已认证身份记录请求 ID、上游响应 ID、开始/结束时间、请求模型及输入/输出/缓存/推理 Token。原 PostgreSQL 账本继续作为具体 Token 的来源。未返回计量保留未知，不补成0。

另在 `CODEX_QUOTA_ATTRIBUTION_FILE + .batches.sqlite3` 保存私有计量镜像、暂估批次和修订记录。文件600权限，不保存提示词、输出、账户授权或设备 Key。上游响应 ID、请求 ID 与来源身份去重绑定；未知→已计量只补全同一记录，不改变原设备或完成时间。广告业务库和表不修改。

主设备通过现有只读本机采集器导出同一组 Token 增量事件，并附原事件时间、可取得的任务开始时间及模型。事件 ID 使用摘要，不导出原会话文本。完整事件数、未知数和总 Token 必须与本机汇总一致，才允许参与估算。原主管窗口与认证不重启、不重新登录，子设备无需改配置。

网关同步镜像失败时保留原计量出站记录重试；采样还会从最近30分钟已提交的网关账本恢复旧格式及升级期间的记录。只有结束时间的恢复记录标为时间依据不完整。源数据超限、身份不符或计量对不上时暂停归属，不丢弃原 Token 账本。

## 暂估批次与观察组

1. 首次健康采样建立新版起点。本人确认与升级前 automatic 结算保持原样，既有待归属不凭历史累计 Token 回填。
2. 此后每次官方已用额度增加，建立唯一批次，保存实际额度采样时间与增量。重复采样或重启不会重复生成批次。
3. 相邻30分钟内的额度增量共享一个观察组；通过原请求时间，将这一段活动的计量归入组内。每条计量只属于一个观察组。各批次按组内已计量总 Token 权重暂估，不按额度返回时哪个设备在线分配。
4. 后续数据即便在官方额度不再变化时才到达，也会按原事件时间进入对应组，并重算该组批次。连续并发时继续展示暂估，不要求全部设备停工。
5. 观察组在最后一笔额度变化30分钟后、且不存在已知未完成/未知计量时，可显示“观察后估算”。这仍不是官方确认；更晚补账仍能修订。持续使用导致额度不断变化时，观察组可能长期保持暂估。

30分钟是本系统的观察策略，不是 OpenAI 的上报延迟上限。更晚的计量只要原时间属于已知组，仍会回算；无法确认覆盖或时期的消耗保留待归属。跨区间长请求标为依据有限，不能据此声称准确扣额。

存在正在执行或未知计量的来源、且该来源还没有可用组内计量时，批次等待回传；已回传部分计量但仍执行其他任务时，可显示低置信暂估。计量完整不等于官方扣额公式已知，不同模型、缓存和推理对额度的权重仍未从接口取得。

## 回算与审计

迟到数据会修订新版估算，可能降低某台设备、提高另一台设备的已归属百分比；具体 Token 的原始归属不变。观察组保存统一版本、前后权重、来源、完整性、时间范围和原因。批次沿用观察组版本，新批次的首个版本可能大于1。

审计按观察组存一份权重向量，避免100个批次把每次修订复制100份；各批次前后的金额通过当时向量和批次增量精确重建。来源汇总随事件归组和未知计量补全同步维护，不需要每次把整周请求装入内存。

页面展示最新12个批次，可点击“查看修订”；管理接口 `GET /api/codex/quota-batches/{batchId}/revisions` 最多返回最近50个组版本。仅管理身份可访问，匿名401，普通运营403。原始修订保留在私有数据库。

“暂估”包含在已归属人员消耗内，不再次相加；“批次待归属”是账户待归属的一部分。历史未分配或尚未采集的新额度可能使账户待归属高于批次待归属。

## 一致性、异常与回滚

- SQLite事务提交计量归组、批次、修订及游标，再原子更新64KiB以内的JSON摘要。两者之间崩溃时从SQLite游标恢复，不重复分配；秒级重置抖动沿用既有窗口身份。
- 本人确认、旧版结算与新版暂估分开合计。已知但不在现行人员中的来源仍保留分母权重，其份额继续待归属，不强行归一化其他人。
- 超过5分钟采样缺口、计数回退、待补账或源身份异常造成的新额度保留待归属。恢复后继续估算新批次，缺口批次不凭猜测回填。
- 官方已用下调时暂停并要求复核，不删旧记录；真正换周期重新建立起点。重置时间相差不超过5秒按同周期处理。
- 明确4xx拒绝且无上游响应ID，不作额度权重；原失败/未知Token记录保留。5xx或断连可能已执行，保守作为未知活动。
- 回滚到rc.8或更早前，先暂停采集器的reconcileAttribution回调，保留JSON和SQLite。不要让旧算法在新版批次之外再次分配同一额度。恢复新版后使用原游标，不重置底账。

## 通知与刷新

保持隔离app-server的account/rateLimits/updated监听；通知作提示，每次主动读取并核验账户。子设备计量提交后经无载荷数据库通知和既有SSH触发复核；主设备每2秒观察新增事件。合并1秒内的触发，读取最短间隔5秒，活动后约15秒追加核验，60秒定时读取兜底；本机用量每30秒上传，页面每15秒刷新。

独立进程未必收到其他客户端的全部官方通知，所以保留主动采集。断线分别按2–30秒退避重连；不把重发快照时间当成额度新采集时间。这些间隔均为本系统设置，不保证官方即时更新。

官方额度接口：[OpenAI App Server rate limits](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)。
