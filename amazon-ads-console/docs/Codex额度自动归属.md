# Codex 额度自动归属 rc.7.2

官方账户容量为100%。人员已归属（本人确认＋自动推定）＋待归属＋剩余＝100%。Token独立计量。并发时以同期已计量总Token为权重估算官方额度增量，明确标为估算；不能据此反推套餐Token容量或API费用。

## 后台流程

主机采集器每约120秒上传官方额度及本机日志计量，再调用当前正式版本 `scripts/reconcile_codex_attribution.py`。配置项 `reconcileAttribution: true` 显式启用；无需打开控制台。服务端核对主机、全部登记设备本期请求（包含停用设备）、待补账和进行中的调用。

单一可见来源仍自动推定。并发时累计上次结算后的各设备Token计数增量，按该区间权重分摊新增的官方账户额度。例：账户增加1个百分点，设备A/B同期可计量Token为600/400，则分别增加0.6/0.4个百分点，分母仍是账户100%，不是把两人显示成60%/40%账户消耗。主机本机日志与各独立设备Key入口同时参与；以前区间、以前设备累计Token不作为新一轮权重，也不重分已有确认或推定。

新启动设备有活动但尚无可计量结果时，本批额度自动等回传，后续即便官方额度没再变化也能结算。连续并发不要求所有设备停工：已有计量的设备即使有后续任务仍能参与；计量不完整/仍有未完请求的估算明确标为低置信。完全未知数量且无任何权重的来源继续等待，不能凭请求次数编造Token。已知但不在现行人员名单中的来源仍计入权重，其那部分保留待归属，不影响其余有效人员的可计算部分。

超过5分钟采集缺口、Token/事件计数回退、待补账或身份不明保守单列。缺口造成的未知历史不会在以后空闲时回填；官方下调暂停推定，新窗口/套餐重新起算。升级沿用上次采集作为新权重起点，不重分旧版已经归属的额度。

## 证据边界

官方没有逐设备额度账单。单一来源标“自动推定”，并发标“并发用量估算”。估算权重仅是同期已计量总Token；不同模型、缓存、输入/输出与推理的官方额度消耗规律未从接口取得，所以这不是官方消耗公式，也不是精确费用。它只覆盖主机被扫描日志与统一入口。整数取整、延迟、跨区间完成的请求和未监测客户端可能产生偏差。未知Token标记继续保留，低置信估算不冒充精确计量。

最近30分钟活动只作为延迟提示：当曾有其他设备近期活动，但本区间没有它的新增计量时，估算也会标为低置信，而不会拿其过去30分钟的累计Token分摊新区间。官方额度改变的时点与真实消耗时点可能错开。每次决策记录统计起止、权重、分配、是否计量不完整，支持事后核对，但不自动重写已经结算的历史。

Token数量未知与身份未知不同：设备Key经服务端绑定身份，未知Token请求或本机分支缺少零基线仍计作该来源的活动，但Token未知标记保留。分支日志只采用第一条本身的session元数据，忽略继承的父元数据，防止合并不同计数器虚增Token。

## 状态、异常与回滚

`CODEX_QUOTA_ATTRIBUTION_FILE` 的600权限文件保存确认、自动记录和游标。共用同名 `.lock`，在锁内原子替换；重放不重复分配，重启保留游标和等待计量批次。新记录按窗口/设备/方法累积摘要，使20设备持续并发不随每次采样无限膨胀。每次分摊的详细审计以 `pendingAudit` 出站队列和分窗口600权限 `.audit.<reset>.jsonl` 追加落盘；先提交分配和出站队列，再写审计，再清队列。崩溃重试可能重复同一decisionId，审计读者须按ID去重，人员额度不会重复分配。摘要64KiB满后暂停，由管理员归档旧窗口，不截断当前账。不要把已有自动记录重复写成确认记录。

模型入口在独立私有 `active/` 目录记录设备标识与开始/结束时间，完成后保留30分钟，供快照交叉核对，再清理；未完成记录持续作为活动证据，进程异常后残留需核对，不能擅自认定零消耗。原终端计量队列仍能重放。

采集失败显示暂停，保留历史；恢复后缺口增量保守单列；等待计量状态则会自动恢复结算。只更新额度采集器，不修改认证或重启原Codex。回滚应用时关闭采集器 `reconcileAttribution`，防止旧应用缺少该入口；保留私有状态，rc.7.2恢复时继续对账。


## 秒级边界与拒绝请求

同套餐/时长、重置时间相差不超过5秒视为同一个窗口，沿用已存在窗口身份，避免官方秒级抖动触发重复归属；真正跨周仍重置。采集器也稳定本机日志的窗口起点。识别出的历史重复推定保留为已取代审计，不重复计入额度。

明确的请求拒绝（400/401/403/404/405/413/422/429且没有模型响应ID）不作为等待模型计量的活动或估算权重。原失败/未知Token账本保留，不声称其Token为0。5xx、断连等可能已执行的情况仍保守对待。旧版未分配增量如需补结算，必须重建未分配区间的实际计量，记录回溯依据，不用全周期Token随意分配，也不动已确认消耗。
