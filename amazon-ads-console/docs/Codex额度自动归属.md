# Codex 额度自动归属 rc.6

官方账户容量为100%。人员已归属（本人确认＋自动推定）＋待归属＋剩余＝100%。Token独立计量，不用Token权重反推额度，不换算为API费用。

## 后台流程

主机采集器每约120秒上传官方额度及本机日志计量，再调用当前正式版本 `scripts/reconcile_codex_attribution.py`。配置项 `reconcileAttribution: true` 显式启用；无需打开控制台。服务端核对主机、全部登记设备本期请求（包含停用设备）、待补账和进行中的调用。

初次对账仅有一个可见来源时，将未分配额度推定到该设备。后续累积自上次额度变化以来的来源，并考虑最近30分钟活动保护期。只有单一设备时自动归属；并发、超过5分钟的采集缺口、计数回退、待补账或身份不明保留待归属，不在以后空闲时回填混合增量。官方向下调整额度时暂停推定；新窗口/套餐重新起算。

## 证据边界

官方没有逐设备额度账单。自动结果标为“自动推定”，仅覆盖主机被扫描日志与统一入口。整数取整、超过保护期的延迟及其他未监测客户端仍会造成不确定，无法保证并发额度精确拆分；每台设备的具体Token仍独立记录。

Token数量未知与身份未知不同：设备Key经服务端绑定身份，未知Token请求或本机分支缺少零基线仍计作该来源的活动，但Token未知标记保留。分支日志只采用第一条本身的session元数据，忽略继承的父元数据，防止合并不同计数器虚增Token。

## 状态、异常与回滚

`CODEX_QUOTA_ATTRIBUTION_FILE` 的600权限文件保存确认、自动记录和游标。共用同名 `.lock`，在锁内原子替换一次提交；重放不重复分配，重启保留游标。64KiB满后暂停，由管理员归档，不能截断当前账。不要把已有自动记录重复写成确认记录。

模型入口在独立私有 `active/` 目录记录设备标识与开始/结束时间，完成后保留30分钟，供快照交叉核对，再清理；未完成记录持续作为活动证据，进程异常后残留需核对，不能擅自认定零消耗。原终端计量队列仍能重放。

采集失败显示暂停，保留历史；恢复后缺口增量保守单列。只更新额度采集器，不修改认证或重启原Codex。回滚应用时关闭采集器 `reconcileAttribution`，防止旧应用缺少该入口；保留私有状态，rc.6恢复时继续对账。
