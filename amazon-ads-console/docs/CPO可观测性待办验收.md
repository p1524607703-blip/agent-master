# CPO 可观测性待办验收

2026-10-06：25项均已实现；本地后端37项、基础设施7项测试通过，前端生产构建通过，并使用模拟数据完成浏览器页面核查。生产部署后的实际版本、请求ID及验收结果另存为生产验收报告，避免把计划当成生产证据。

| 项 | 待办 | 实现与验证 |
|---|---|---|
| 1 | journald 容量与留存 | 2GiB / 最长30天，持久存储 |
| 2 | 独立 API access log | JSON，endpoint与状态/耗时 |
| 3 | Nginx logrotate | 每日/容量触发，30档/最长30天 |

| 8 | L1/L2指标 | 命中、未命中、过期、错误 |
| 9 | 构建锁指标 | 取得/超时/等待时间 |
| 10 | 数据库指标 | psql_calls与db_wall_ms |

| 25 | 系统诊断页 | 管理层按ID/时间/用户检索当前及轮转日志 |

浏览器附加链路：page_enter、api_start、api_end、render_complete，内存中最多300条；不记录密码、token、请求body或原始query，退出登录时清空。

限制：30天为最长保留，容量轮转可能提前淘汰；诊断单次扫描64MiB/10万行、最多200条并提示截断。未启用日志前的请求无法回补。Redis中断时只保证单个worker的降级互斥；正常Redis支持跨worker互斥。告警可在系统日志与Cockpit查看，不自动向外部聊天发送。

人工入口及部署/回滚步骤见《CPO日志与发布运行手册》。
