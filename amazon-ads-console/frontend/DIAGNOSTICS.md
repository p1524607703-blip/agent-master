# CPO 加载排查

运营详情与“我的 CPO”的数据质量区显示完整性判定、缺业务侧产品数量及清单、未配对广告花费和三项来源的日期覆盖。来源未覆盖日期可展开查看日期及服务端返回的待补账户。产品缺业务侧记录与整份报告未导入是不同情况，不根据产品清单推断报告导入状态。三项来源各自的日期覆盖与同时完整的日期交集分别展示。

读取失败会显示错误，本次口径标为待确认，不会把上一次读取结果当成本次完整数据。切换日期或运营时，较早返回的请求不会覆盖较新的选择。

管理层和超级管理员可以打开“系统诊断 / 请求追踪”，按请求 ID、用户 ID、用户名、接口、开始和结束时间查询。请求表展示版本、提交、revision、缓存计数、锁等待、数据库耗时与调用次数、构建和总耗时以及状态码。选择一条记录可查看角色、运营组、日期范围、进程、锁计数及异常调用栈，并复制或下载诊断证据。时间输入使用当前浏览器时区，发送查询时转换为 UTC。

服务端日志最长保留 30 天，容量限制可能使日志提前轮转。页面会展示扫描截断提示；截断时没有匹配结果不能证明更早的日志不存在。

复现慢加载时，可以在同一个浏览器标签页按以下步骤保存证据：

1. 打开出现问题的 CPO 页面，选择日期或运营并等待结果或错误出现。
2. 使用数据质量区的“复制加载记录”或“下载加载记录”。管理层也可在诊断页更新、复制或下载当前浏览器记录。
3. 提供问题现象、选择的日期/周期以及记录中的请求 ID。管理层用该 ID 查询服务端记录，比较浏览器、数据库、锁和构建耗时。

浏览器只在当前标签页内存保留最近 300 条事件，刷新或退出登录后清空，不上传到外部服务。记录只包含时间、页面路径、接口路径、请求 ID、状态和耗时，不保存令牌、请求头、请求正文或 URL 查询参数。`api_start` 到 `api_end` 测量请求发出至响应头收到；`render_complete` 的 `data` 阶段表示请求结果已更新到页面 DOM，`shell` 阶段表示页面框架已更新。它们不是浏览器完成绘制的精确时刻。

本地浏览器检查使用模拟接口核验界面与权限。`artifacts/data-quality-preview.png` 和 `artifacts/cpo-diagnostics-preview.png` 带有 Mock 水印，仅用于界面预览，不代表线上实时状态。
