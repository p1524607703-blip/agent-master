## 四、关键决策记录

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 目录结构 | 完全新建 Karpathy 三层 | 用户明确要求完全按 Karpathy 方案 |
| 选品工具 | 移出 vault | 避免代码污染知识库 |
| 重复目录 | 删除 ai研发+电商数据知识库/ | 对比确认主目录为权威版本 |
| CLAUDE.md | 拆分为 CLAUDE.md + AGENTS.md | 技术与知识规则分离 |
| 现有编号体系 | 废弃，全部按主题重组 | 完全采用 Karpathy 扁平主题分类 |
| .obsidian/ .claude/ .learnings/ | 保留不动 | 这些是工具层基础设施，不属于知识架构 |

## 五、预设假设

1. **Obsidian 按文件名匹配 Wikilinks**：移动文件后，`[[文件名]]` 类型的 wikilinks 仍可正常工作，Obsidian 会按文件名搜索而非按路径。移动后需打开 Obsidian 让它重新索引。
2. **选品工具的磁盘空间充足**：移到 vault 同级目录约需 数百 MB（主要是 node_modules）。
3. **Git 历史不保留在 vault 内**：移动操作会丢失单个文件的 Git 历史，但不影响 vault 级 git 的旧版本记录。
4. **Skills 体系的 .claude/skills/ 路径引用无需修改**：Skills 中如果有硬编码的文件路径（如 `01-产品/`），实施时需逐一检查并更新。
