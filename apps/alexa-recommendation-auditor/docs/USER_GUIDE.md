# Alexa 商品推荐诊断插件使用手册

> 对应应用版本：`0.1.0`
>
> 本地事实源：`docs/USER_GUIDE.md`；团队共享版本同步到固定飞书使用手册。

> 面向亚马逊运营、商品负责人和测试人员。本手册说明如何安装、运行和解读测试结果，不包含系统开发实现或任何访问凭据。

## 1. 工具用途

Alexa 商品推荐诊断插件用于观察：

- 当前鞋类商品是否会进入 Alexa for Shopping 的完整返回商品列表；
- 商品在哪些品类、受众、功能、脚型、场景和材质意图下更容易被推荐；
- 商品未进入推荐时，现有公开证据能够支持哪些原因判断；
- Alexa 的文字解释与实际推荐卡片是否一致；
- 同一意图采用直接属性与自然语言表达时，推荐结果是否一致。

本工具测量的是公开页面与实际 Alexa 对话中的可观察行为，不能证明 Amazon 内部算法、真实权重或隐藏召回逻辑。

## 2. 使用前准备

开始前请确认：

1. 已安装 Google Chrome，并允许加载本地扩展。
2. 已取得本项目完整文件，且本地服务可以正常启动。
3. 已使用专用测试账户登录 Amazon.com。
4. 当前站点为美国站 `https://www.amazon.com/`。
5. 测试期间不同时操作 Alexa、不切换商品、不加购或购买。
6. Hermes 模型通道如需启用，应由开发维护人员提前配置。模型不可用不影响固定模板测试。

建议先用“冒烟”预设验证完整链路，再执行“校准”或“完整”测试。

## 3. 首次安装与加载

### 3.1 启动本地服务

打开终端并执行：

```bash
cd "/Users/panjinlong/Documents/agent-master/apps/alexa-recommendation-auditor"
npm install
npm run dev
```

首次安装需要执行 `npm install`；后续日常使用通常只需执行 `npm run dev`。

请保持终端窗口运行。默认本地服务地址为：

```text
http://127.0.0.1:4318
```

### 3.2 加载 Chrome 扩展

1. 在 Chrome 地址栏打开 `chrome://extensions`。
2. 打开右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择以下目录：

```text
/Users/panjinlong/Documents/agent-master/apps/alexa-recommendation-auditor/extension/dist
```

5. 将“Alexa 商品推荐诊断”固定到浏览器工具栏。
6. 点击扩展图标，打开右侧侧边栏。

插件升级或重新构建后，请在 `chrome://extensions` 中点击该扩展的“重新加载”，再刷新 Amazon 页面。

## 4. 连接本地服务

侧边栏首次打开时会显示“连接本地服务”。

1. 确认服务地址为 `http://127.0.0.1:4318`。
2. 点击“检查连接”。
3. 看到“本地服务已连接”后继续。

开发模式通常免配对。如果正式运行环境要求配对：

1. 从本地服务启动终端中取得当次六位配对码。
2. 在侧边栏输入配对码。
3. 点击“完成配对”。

配对码只能使用一次，不要将配对码或其他认证信息写入测试记录或共享文档。

### Hermes 状态

连接成功后，侧边栏会显示“Hermes 模型通道”：

- `API Server 在线`：可尝试对固定问题做受控语言改写和诊断解释；
- `不可用`：系统自动使用固定模板和确定性诊断，测试仍可继续；
- “打开 Hermes 日志”：用于查看当次模型请求状态，由开发维护人员排查。

Hermes 只辅助问题表述和原因解释，不负责操作浏览器，也不决定推荐指数。

## 5. 建立商品基准

### 5.1 打开商品详情页

使用专用测试账户打开待测试鞋类商品的 Amazon.com 详情页，并等待标题、规格、Bullet、A+ 和 Alexa 面板加载完成。

尽量保持：

- Amazon 页面语言固定；
- 配送地址固定；
- 测试账户固定；
- 选中的颜色和尺码固定；
- 页面上没有 CAPTCHA、登录失效或异常提示。

### 5.2 读取当前页面

1. 打开插件侧边栏。
2. 填写“测试账户标签”，例如 `us_test_account_01`。不要填写真实姓名、邮箱或账号密码。
3. 点击“重新读取”。
4. 检查侧边栏显示的 ASIN、商品标题和品牌。
5. 检查“稳定证据”和“零售信号”的数量是否合理。

稳定证据主要用于产品类型、受众、功能、身体需求、场景和材质等意图判断。价格、库存和配送属于易变零售信号，仅作为独立观察条件。

如果读取到的 ASIN 或标题不是当前商品，请不要继续生成问题，先刷新 Amazon 页面并重新读取。

### 5.3 同步到 Amazon 图片工作台

这是独立于推荐指数测试的辅助功能，不要求侧边栏正在运行测试：

1. 在 Chrome 中打开目标 Amazon 商品详情页，等待标题和五点加载完成，并复制地址栏中的商品链接。
2. 打开本地或 GitHub Pages 版“亚马逊图片工作台”，进入 Listing / A+ 策划模块。
3. 粘贴商品链接并点击“按链接同步”。扩展只读取站点和 ASIN 与链接精确匹配的已打开商品页；它不会猜测最近使用的页面，也不会新开窗口、切换标签页或把商品页跳回首页。
4. 核对预览中的站点、ASIN、标题、品牌和证据数量，再点击确认导入。同步本身不会调用 AI、生成图片或产生模型费用。
5. 检查并修改自动填入的 Listing 与商品信息，确认无误后再手动点击“AI 策划”。

自动同步只带入标题、品牌、类目、五点、稳定规格和 A+ 正文。价格、促销、库存、配送、卖家、评分、评论、Q&A、Rufus/Alexa 对话和账户信息不会进入图片策划。最后成功快照最多保留 15 分钟；当前商品页读取失败时，仅允许回退到相同 ASIN，出现 ASIN 不一致提示应刷新正确商品页，而不是继续导入。

每次确认导入都会清空上一轮提示词、策划卡片和当前策划会话。切换到新 ASIN 还会清空旧商品参考图和风格；同一 ASIN 刷新只保留用户明确上传的商品参考图。手动输入、粘贴 JSON 和导入 JSON 文件始终可用。

如果出现“扩展后台没有响应”，请在 `chrome://extensions` 对从 `extension/dist` 加载的“Alexa 商品推荐诊断”点击“重新加载”，随后刷新图片工作台。如果提示找不到目标商品页，检查粘贴链接与已打开页面是否属于同一站点、同一 ASIN。

## 6. 选择语言与题集

### 6.1 提问语言

当前支持：

- 英语（Amazon US）
- 简体中文

两种语言使用相同的测试槽位、页面证据、问题角色和评分口径，只改变向 Alexa 提问的措辞。切换语言后需要重新生成问题集。

为提高不同运行之间的可比性，同一批测试应始终使用相同语言。

### 6.2 运行预设

| 预设 | 规模 | 适用场景 |
|---|---:|---|
| 冒烟 | 3 个独立新会话对照题 + 2 个单会话递进题 | 首次安装、页面适配和会话复用测试 |
| 校准 | 5 个独立新会话对照题 + 4 个单会话递进题 | 日常诊断、Alexa 自评分、筛选透明度和无品牌进入假设 |
| 完整 | 5 个独立新会话对照题 + 6 个单会话递进题 | 加入场景收窄、标准价格带复评分和完整候选轨迹 |

每个问题只执行一次。任一产品的独立新会话题不得超过5个，单一对话框中的递进题不得超过6个；服务端会在生成、编辑和审批时再次校验。完整测试耗时较长，应在冒烟测试成功后再执行。

两条轨道的会话方式不同：

- **独立新会话对照组**：每题新建 Alexa 会话，顺序按运行种子稳定随机化，用于降低上一题上下文污染。只有页面证据对齐的正向题可能进入主推荐指数。
- **单会话递进组**：第一题建立自然候选集，后续问题复用同一对话框，依次取得 Alexa 自定义推荐指数、追问筛选透明度、生成无品牌进入假设，并在完整预设中继续做场景和预算收窄。该组不进入主推荐指数。

## 7. 一键查看推荐指数

### 7.1 主流程

确认商品基准后，点击“查看推荐指数”。这是日常使用唯一需要点击的主按钮。

系统会依次自动完成：

1. 没有可用题集时，按当前语言和预设生成问题；
2. 校验题文、页面证据、测试角色、题数和会话轨道；
3. 审核并锁定通过校验的题集；
4. 创建隔离后台 Amazon 工作区；
5. 自动发送全部问题并记录结果；
6. 完成后再次点击同一按钮打开完整报告。

不需要再勾选安全确认、点击“审核通过”、点击“开始测试”或逐题点击 Rufus 发送按钮。验证码、限流、登录失效和选择器漂移仍由系统自动安全停止。

如果已有失败或中断运行仍包含待执行问题，再次点击“查看推荐指数”会续跑原题集，不会重新生成问题、覆盖商品基准或重复计算已完成轮次。

### 7.2 高级设置与审计（可选）

语言、预设、问题人工编辑、评分规则和运行日志位于默认折叠的“高级设置与审计”。展开后可查看：

- 固定模板数量；
- Hermes / DeepSeek 改写数量；
- 人工调整数量；
- 模型状态、耗时和会话标识；
- 如发生回退，对应的安全原因。

逐项展开问题，至少检查：

1. **Alexa 问题**：语句是否自然，是否符合所选语言。
2. **测试角色**：是正向计分、基线、负向对照、零售探针、辅助识别还是诊断。
3. **会话轨道**：是“独立新会话对照”还是“单会话递进”；递进题的顺序和会话组不能随意打散。
4. **预期结果**：商品是否应满足问题条件。
5. **页面证据 ID**：正向条件是否有当前页面的明确证据。
6. **测试假设**：该题实际在验证什么。
7. **人工审阅清单**：测试后应如何核对结果。

模型改写不能加入页面没有证明的新功能、疗效、使用任务或适用人群。

配置页提供 5 个 AI 建议问题方向：价格带、场景、材料/结构、风险反证和自然用户问法。它们是可替换 P4—P6 的审核选项，不会自动增加题数；建议问法必须绑定页面证据，并由后续独立新会话实际验证。

问题默认不指定“推荐 5 款”等固定数量，由 Alexa 按正常购物问答方式决定返回多少候选；插件会保存回答中全部可识别的商品链接和无链接商品卡，而不是只保留前五名。

### 7.3 修改或停用问题

需要调整时：

1. 修改“Alexa 问题”文本；
2. 在“调整原因”中说明原因；
3. 点击“保存该问题”。

不适合当前商品的问题可以取消勾选“启用这个问题模板”。停用问题不会进入执行队列，也不会进入主指数。不要把独立题改成递进题来绕过5题上限，也不要把递进题改成独立题来改变计分范围；服务端会拒绝超过轨道上限或出现多个递进会话组的题集。

如果存在未保存草稿，一键主流程会先保存草稿，再自动校验和锁定；也可以在高级设置中提前逐题保存或点击“保存全部草稿”。

### 7.4 自动审批与锁定

正常主流程不需要手动审批。点击“查看推荐指数”后，系统会调用同一套服务端规则自动校验并锁定问题集；高级区域仍保留人工审批按钮，供开发调试使用。

锁定后：

- 问题不能被静默修改；
- 运行日志会记录审批版本；
- 校验通过后立即进入后台测试。

如需改变语言、预设、商品基准或大量修改题目，应重新生成问题集，而不是继续使用已锁定的旧题集。

## 8. 查看运行日志

“运行日志”用于检查问题从生成到运行的完整过程，包括：

- 问题集生成；
- 固定模板或 Hermes 改写来源；
- 模型回退原因；
- 人工修改及问题集版本；
- 审批锁定；
- 每轮开始、完成或失败；
- Alexa 回答字符数、DOM 链接数和完整候选数量；
- 约束和证据判断；
- 分数重算；
- 自动安全停止及其原因。

点击“刷新”可读取最新日志。日志刷新失败不会删除上一次已成功读取的内容。

运营人员重点核对：

- 实际发送的问题是否与审核版本一致；
- 问题语言是否正确；
- 正向计分题是否有页面证据；
- Alexa 返回的商品卡是否被正确解析；
- 安全停止原因是否明确。

如果首轮出现 `selector_drift / Alexa输入框未出现`，系统会停止剩余题目。请先重新加载最新版扩展并刷新 Amazon 页面，再重新生成冒烟题集；不要直接继续旧运行。

如果问题已经显示在输入框中但没有自动发送，不要逐题手动点击。最新版会等待 Rufus 的发送按钮启用后自动提交；若仍失败，会保存提交控件诊断并安全停止。重新加载扩展后应创建新的冒烟运行，旧失败运行不适合继续作为干净样本。

如果看到 `A listener indicated an asynchronous response ... message channel closed`，表示问题处理期间测试页面发生了跳转或销毁。旧版可能在这种错误后重复发送问题并立即关闭测试窗口；最新版不会重发状态不明的问题，并会把当前窗口里的后台测试标签页保留 60 秒供检查。不要在该标签页中手动再次发送；重新加载 `extension/dist` 后应创建新的冒烟运行，已发生状态不明提交的旧运行不适合作为干净样本。

如果底部仍显示原样的 `tabs.get(integer tabId...): No matching signature`，说明 Chrome 正在运行旧的 service worker，而不是刚构建的扩展。最新版自动执行器既不调用 `tabs.get()`，也不调用 `windows.create()`，并会在启动前检查侧边栏与后台的协议/构建版本。请先关闭当前侧边栏，打开 `chrome://extensions`，确认扩展来源是本项目的 `extension/dist`，点击该扩展的“重新加载”，再重新打开侧边栏；若仍未更新，删除该扩展后从同一 `extension/dist` 目录重新“加载已解压的扩展”。加载最新版后，版本错配会被直接拦截；其他执行错误会包含 `[执行阶段]` 和 `executor 2026.07.17-no-window-prompt-isolation.1`。

## 9. 开始与观察测试

### 9.1 开始前检查

1. 保持 Chrome 和本地服务运行即可；当前前台可以是 Amazon、图片工作台或其他页面，无需返回待测商品页。
2. 点击“查看推荐指数”。问题集生成、审批锁定和启动均自动完成。

正常情况下只需点击这一次。后续问题会按题集自动执行：独立题自动创建新会话，递进题自动复用同一会话，每轮至少间隔 12 秒；不需要逐题点击发送或再次点击开始。

如果侧边栏恢复的是旧 prompt 版本且仍有待执行题目，这次点击会自动重新生成当前版本题集，不会续跑旧问题；已完成的旧运行仍可作为历史报告查看。

商品基准在生成并审批问题集时已经锁定。开始阶段不会用当前页面覆盖基准，也不会检查当前标签页 ASIN。扩展只会在当前 Chrome 窗口创建一个非活动 Amazon 测试标签页，整个运行共用这一个标签页，绝不新建浏览器窗口。独立题返回 Amazon 首页、新建 Alexa 对话和强制刷新都只发生在该后台标签页，不会让你正在查看的商品页跳转，也不会让前台 Alexa 对话框消失。

### 9.2 运行期间

运行期间请：

- 保持 Chrome 和本地服务运行；
- 可以继续浏览和切换前台标签页；不要关闭、导航或操作扩展创建的非活动 Amazon 测试标签页；
- 不在该后台测试标签页的 Alexa 面板中手动发送问题；
- 不修改已选颜色或尺码；
- 不进行加购、购买或账号设置操作；
- 不尝试处理或绕过 CAPTCHA。

每轮之间至少等待 12 秒。每道独立题都会从新的 Alexa 对话开始，且题目开头会明确要求“仅依据本条需求回答，不引用或延续任何先前对话”；递进组只在 P1 使用这段隔离提示，P2 以后按设计承接同一对话。系统还会检查页面是否真的没有上一题历史，无法证明干净时直接停止。这些措施不会清除 Amazon 账户级个性化。

### 9.3 自动停止与恢复

主界面不再提供人工运行控制。系统遇到 CAPTCHA、限流、登录失效、权限错误或连续失败时会安全停止，保存已完成轮次，并把未执行题目保留为待运行状态。

问题处理完毕后再次点击“查看推荐指数”，系统只执行仍处于待运行状态的题目，不会重复计算已经完成的轮次。开发调试需要主动终止时，可停止本地服务或关闭扩展创建的非活动后台测试标签页。

切换标签页、关闭侧边栏或销毁侧边栏页面不会终止仍在运行的后台循环；重新打开侧边栏会恢复显示进度。不要关闭或导航扩展创建的专用 Amazon 测试页。如果扩展本身被重新加载而服务端仍显示 `running`，再次点击“查看推荐指数”即可继续未完成问题。已经完成的问题不会再次发送。

### 9.4 自动安全停止

出现以下情况时系统会停止，不会尝试规避：

- CAPTCHA 或 Robot Check；
- 403、429或明显限流；
- Amazon 登录失效；
- Alexa 关键页面元素无法识别；
- 连续三轮解析失败；
- 本地执行异常。

发生安全停止后，应先保留日志和截图，再由开发维护人员确认原因。不要立即连续重试。

## 10. 查看和解释报告

完成至少一轮测试后，点击“查看完整报告”。报告会在新标签页打开。

### 10.1 Alexa 推荐指数

主指数由可复算规则计算：

```text
35% × 完整返回列表进入率
+ 25% × 标准化排名
+ 15% × 竞品比较胜率
+ 15% × 页面证据承接度
+ 10% × 同一意图直接表达/自然语言表达的一致性
```

只有同时满足以下条件的完成轮次才可能进入主指数：

- 正向计分题；
- 题目属于独立新会话对照组；
- 商品按问题设计应当满足条件；
- 题目绑定有效的卖家页面证据；
- 商品卡结果可以被归属到我方商品家族；
- 轮次完成且通过代码评分资格检查。

评级含义：

| 评级 | 含义 |
|---|---|
| 强 | 当前有效样本中的综合推荐表现较强 |
| 中 | 有一定召回或排名表现，但仍存在明显缺口 |
| 弱 | 当前有效样本中的推荐进入率、排名或证据承接较弱 |
| 样本不足 | 未达到展示可信数值所需的独立正向样本、意图组、比较题或证据完整度 |

“强、中、弱”只描述本次测试环境中的相对表现，不代表 Amazon 官方评级。

### 10.2 独立探针

以下轨道或题型单独展示，不改变主指数：

- **单会话递进轨迹**：观察条件增加、改写和删除后的完整候选保留率及我方商品进出；
- **宽泛品类基线**：观察自然发现能力；
- **负向对照**：检查不兼容条件下是否能正确排除；
- **解释诊断**：记录 Alexa 的自述原因。

Alexa 的文字解释属于自述证据，必须与完整返回商品卡、排名和页面事实交叉核对。

### 10.3 建议优先阅读的区域

1. 推荐指数、有效样本和置信区间；
2. 各意图槽位的进入率与平均排名；
3. 高频竞争商品；
4. 约束结果、证据结果和原因码；
5. Alexa 自述与商品卡不一致记录；
6. 每轮原始问题、回答、完整返回商品列表和截图；
7. Listing、SP、SBV、SD、STV建议及其证据基础；
8. 完整审计日志。

广告建议仍需结合广告后台绩效、利润、库存和业务目标人工决策，不能只依据 Alexa 测试直接调整预算。

## 11. 常见问题

### 11.1 显示“本地服务未启动”或无法连接

- 确认终端中的 `npm run dev` 仍在运行；
- 确认服务地址为 `http://127.0.0.1:4318`；
- 不要把地址改成 Amazon 页面地址或 Hermes 日志地址；
- 重启本地服务后重新点击“检查连接”。

### 11.2 出现 `401 配对码无效或已经使用`

- 配对码为一次性代码，不能重复使用；
- 正式模式下重启本地服务，使用新显示的配对码；
- 开发模式原则上免配对，如仍要求配对，请联系开发维护人员检查启动配置；
- 不要反复尝试旧配对码。

### 11.3 出现 `500 Internal server error`

- 保留侧边栏错误文本；
- 查看本地服务终端的对应错误；
- 确认扩展已经重新加载，前后端版本一致；
- 重启本地服务并重新读取商品；
- 仍失败时，将运行 ID、时间和错误信息交给开发维护人员，不要提交账号信息。

### 11.4 Hermes 显示不可用

固定模板仍可正常生成和运行。问题会标记为固定模板或安全回退。若需要模型增强，请在 Hermes 日志中确认服务状态，并联系维护人员处理。

### 11.5 无法读取商品页

- 确认当前活动页为 Amazon.com 商品详情页，而不是搜索结果页、购物车或订单页；
- 等待商品标题和详情完全加载；
- 刷新页面后重新读取；
- 在 `chrome://extensions` 重新加载扩展，再刷新 Amazon 页面；
- 暂时关闭会大量改写页面结构的翻译或美化扩展后重试。

### 11.6 读取到错误 ASIN 或商品

不要继续测试。刷新页面，重新选择目标颜色和尺码，再点击“重新读取”。确认标题和 ASIN 后重新生成问题集。

### 11.7 无法审批问题集

常见原因：

- 有未保存的问题草稿；
- 所有问题都被停用；
- 问题集已经锁定；
- 当前启用题中没有页面证据对齐的正向计分题。

按界面提示保存草稿、重新启用合适的问题，或重新读取页面并生成题集。

### 11.8 “查看推荐指数”按钮不可用

请检查：

- 本地服务是否在线。
- 本地服务需要配对时，是否已完成配对。
- 是否已有测试正在运行；运行中按钮会显示进度并暂时禁用。

### 11.9 测试被安全停止

查看侧边栏状态和运行日志中的停止原因。遇到 CAPTCHA、403、429或登录异常时不要立即重跑；先等待并由人工确认账号和页面状态。

### 11.10 报告显示“样本不足”

这通常表示：

- 正向计分题完成数量不足；
- 独立正向意图组不足，或比较题没有完成；
- 商品卡无法稳定归属到我方商品；
- 页面证据或商品卡证据不足；
- 运行被提前停止。

“样本不足”不是零分。应先补足有效测试或修正解析问题，再比较推荐表现。

### 11.11 报告无法打开

- 确认本地服务仍在运行；
- 确认该运行至少记录了一轮结果；
- 重新点击“查看完整报告”；
- 如浏览器地址中的运行 ID 缺失或错误，从侧边栏恢复对应运行后再次打开。

## 12. 隐私、安全与使用边界

插件遵循以下边界：

- 只读取用户已打开 Amazon 商品页中公开显示的内容；
- 不读取 Amazon 密码、Cookie、会话令牌或支付信息；
- 不调用 Amazon 隐藏接口，不拦截私有网络请求；
- 不自动加购、下单或修改账户；
- 静默后台模式不截取前台页面；测试数据、日志和 DOM 提取结果保存在本机；
- 遇到验证码、限流或权限异常时停止，不绕过安全控制；
- 每次运行都必须由用户明确点击开始；
- 一次只执行一个问题，并保持最低时间间隔。

测试人员仍应在保存或分享截图前人工检查是否含有个人信息。不要把真实账户名、邮箱、地址、配对码或任何密钥写入测试账户标签、问题文本或报告备注。

## 13. 推荐的标准测试流程

为了便于不同日期和商品间比较，建议固定以下流程：

1. 使用同一个专用测试账户和配送地址；
2. 固定 Amazon 页面语言；
3. 记录目标父/子 ASIN、颜色和尺码；
4. 执行一次冒烟测试；
5. 审核页面证据和问题集；
6. 使用同一提问语言执行校准测试；
7. 正式分析时执行完整测试；
8. 不删除失败轮次，保留安全停止和解析日志；
9. 报告中同时记录测试日期、账户标签和运行 ID；
10. 只在相同预设、语言和测试环境下横向比较分数。

## 14. 日常结束操作

测试结束后：

1. 确认运行状态为 `completed` 或已明确停止；
2. 打开报告并检查截图、完整返回商品列表和原因码；
3. 记录运行 ID；
4. 停止本地开发服务；
5. 退出专用 Amazon 测试账户；
6. 按团队规范归档或同步报告，不单独分享含个人信息的原始截图。
