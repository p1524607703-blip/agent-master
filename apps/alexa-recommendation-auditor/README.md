# Alexa 商品推荐诊断

本地单机的 Chrome MV3 鞋类黑盒测试工具。它适用于人字拖、凉鞋、乐福鞋、套脚鞋、赤足鞋、跑鞋、步行鞋、靴子等鞋类，而不是为某个 ASIN 写死题目。系统从当前 Amazon 商品详情页建立可审计基准，以“固定可比模板 + 页面证据动态槽位 + 经 Hermes Agent 的受控 DeepSeek 改写”生成问题，通过用户明确启动的 Alexa for Shopping 对话直接读取回答 DOM，并保存完整可识别商品列表，再用确定性公式计算推荐指数。

## 组成

```text
extension/          Chrome 侧边栏、Amazon PDP/Alexa 适配器、隔离后台状态机与图片工作台桥接
server/             NestJS、Prisma/SQLite、Hermes模型通道、评分、诊断和本地报告接口
report/             Vue + Element Plus + ECharts 独立报告页
packages/contracts/ 共享 TypeScript 类型、JSON Schema 与评分公式
```

DeepSeek通过本机 Hermes Agent API Server 负责商品意图结构化、问题表述和诊断解释；插件服务绝不直连DeepSeek。模型不能直接控制浏览器、添加未经页面证明的条件，也不能决定最终分数。页面交互只允许固定状态机中的“新会话、填写问题、提交、等待、解析、截图”。模型生成/改写后的完整题目、原始固定模板、改写原因、证据 ID、预期结果和审阅清单都会进入运行日志。

## 首次安装

```bash
cd "/Users/panjinlong/Documents/agent-master/apps/alexa-recommendation-auditor"
npm install
cp .env.example .env
npm run dev
```

模型增强只连接本机 Hermes Agent。先在 Hermes 中配置模型凭据并启用 `api_server`，默认接口为 `http://127.0.0.1:8642/v1/chat/completions`；本项目 `.env` 只配置 `HERMES_API_URL`、`HERMES_MODEL=hermes-agent`、可选的 `HERMES_API_KEY` 和 `HERMES_DASHBOARD_URL`。DeepSeek凭据不得写入本项目，任何 `DEEPSEEK_*` 环境变量都会被忽略。

```bash
hermes gateway status
hermes gateway run
```

Hermes不可用、超时、返回5xx、余额不足导致非JSON回答，或模型输出未通过本项目JSON Schema和业务校验时，系统只会退回固定模板/确定性诊断，不会绕过Hermes直连模型。审计记录会保存安全原因码、Hermes Session ID、耗时和token用量，但不保存供应商错误正文或凭据。侧边栏的“打开 Hermes 日志”默认指向 `http://127.0.0.1:9119`。

开发模式默认只监听 `127.0.0.1` 并免配对，便于快速验证。打开 `chrome://extensions`：

1. 开启“开发者模式”。
2. 选择“加载已解压的扩展程序”。
3. 选择 `extension/dist/`。
4. 点击扩展图标打开右侧侧边栏，连接本地服务后即可开始。

正式启动（`npm start`）仍要求六位配对码。也可通过 `.env` 中的 `LOCAL_AUTH_MODE` 显式控制：`disabled` 为免配对，`pairing` 为强制配对，`auto` 为开发免配对、生产强制配对。

## 使用流程

1. 使用专用测试账户登录 Amazon.com 并打开我方鞋类商品详情页。
2. 在侧边栏中点击“重新读取”，检查父/子 ASIN、标题、鞋类意图和证据数。
3. 点击唯一主按钮“查看推荐指数”。系统会按当前预设自动生成、校验、审核并锁定题集，然后在隔离后台工作区连续执行全部问题；无需勾选确认、逐题发送或再次点击开始。
4. 测试完成后再次点击“查看推荐指数”打开完整报告。语言、预设、问题编辑、评分规则和审计日志保留在默认折叠的“高级设置与审计”中。

点击“查看推荐指数”后，执行器会自动提交全部后续问题并按至少 12 秒的间隔递进；不需要人工逐题点击 Rufus 发送按钮。独立题切换页面、Alexa 面板重建和脚本版本校验只发生在专用后台工作区，前台页面可继续正常浏览；关闭侧边栏也不会中断后台循环。若扩展此前在第一题前因执行器错误停止，同一按钮会续跑现有已锁定题集，不会重复生成或改变商品基准。

扩展还为亚马逊图片工作台提供版本化 JSON 桥接。图片工作台发起同步时，用户先粘贴 Amazon PDP 链接，扩展按链接中的站点和 ASIN 精确选择已经打开的对应商品页；不会依据最近访问顺序猜测，也不会激活、导航或新建标签页/窗口。标题、品牌、类目、Bullet、稳定规格和 A+ 正文会先进入预览，用户确认后才填入策划表单；价格、优惠、配送、库存、卖家、评论、评分、Q&A、Rufus/Alexa 对话和账户信息全部排除。15 分钟缓存只允许回退到同一 ASIN，手动文本、粘贴 JSON 和导入 JSON 文件仍可继续使用。

独立新会话对照组中的每道题都会新建 Alexa 会话，并按运行种子稳定随机顺序执行；单会话递进组的第一问新建会话，后续最多5问在同一对话中按固定顺序增加、转换或删除条件。这不能清除Amazon账户级个性化。主推荐指数只使用页面证据对齐的独立正向对照题；递进组只用于观察上下文保留和候选集合变化。

## 问题生成与开发日志

- 固定模板分为两轨：独立新会话对照组覆盖严格品类全候选基线、主要功能直接表达、自然需求表达、公开证据比较和负向品类对照；单会话递进组依次建立自然候选集、获取 Alexa 自定义推荐指数、追问筛选透明度、生成无品牌进入假设、按场景收窄，并按运行前锁定的标准价格带复评分。
- 英语与简体中文共用同一组测试槽位、双轨会话策略、证据映射、角色和计分口径；语言选择只改变固定题和动态槽位的提问措辞，并随运行记录持久化。
- 动态槽位只绑定标题、规格、Bullet、A+和类目路径中可以定位的页面证据。评论摘要与Q&A可作为诊断参考，但不能把卖点升级为正向主计分事实。
- Hermes / DeepSeek只能在保留题目语言、必需词、角色、假设、预期结果和证据映射的前提下改写自然语言。中文改写必须保持简体中文；校验失败时回退到对应语言的确定性固定模板。
- 新运行先保存为 `draft`；一键主流程会自动校验并批准为 `ready`。开发者仍可在高级设置中先编辑文本或停用模板，每次修改都会产生版本号和前后对照审计事件。
- 运行日志保留 `question_plan_generated`、Hermes Session和模型调用审计、人工修改、批准锁定、逐轮原始结果、机器判断、分数重算和安全停止事件。
- 配置页展示价格带、场景、材料/结构、风险反证和自然用户问法 5 个 AI 建议方向；它们只能替换 P4—P6，不会突破 5+6 上限，且必须绑定页面证据后再由新会话验证。

## 安全停止

以下情况会立即停止，不会尝试规避：

- CAPTCHA/Robot Check
- 403、429或明显限流提示
- 登录失效
- Alexa关键页面元素漂移
- 连续三轮解析失败

扩展不调用隐藏接口、不读取Cookie、不拦截私有网络请求、不绕过验证码、不加购或购买。每次运行必须由用户点击开始，一次只执行一个问题，每轮间隔至少12秒。

## 推荐指数

```text
35% × 完整返回列表进入率
+ 25% × 标准化排名
+ 15% × 竞品比较胜率
+ 15% × 页面证据承接度
+ 10% × 同一意图直接表达/自然语言表达的一致性
```

只有同时满足 `独立新会话 + positive_control + scoreEligible + expectedMatch=eligible + 有效卖家页面证据 + completed` 的轮次进入主指数。单会话递进、基线、负控制和诊断题均单独报告。

每轮机器判断依据是版本化代码规则：我方父体、当前子体或ASIN别名是否进入 Alexa 完整返回列表、首次排名、比较题是否排名第一、商品卡证据是否承接全部绑定事实，以及同一逻辑意图的直接表达与自然语言表达候选集合 Jaccard 一致性。题目里的 `judgmentCriteria` 是供开发者检查的人工审阅说明，不会静默改写评分公式。

开发者侧边栏和独立报告页都会完整展示主分资格、角色隔离、约束结果、证据结果、词法证据匹配算法、独立探针、精度门槛和原因码词典。只读标准可通过 `GET /api/v1/scoring-standards` 复核；该端点不含运行数据或凭据，在生产配对模式下也可访问。证据匹配只读取可归属到我方商品卡的 `evidenceText`：规范化后若事实值整句命中，或事实值/页面原文的非停用词至少命中 `min(2, token数)` 且覆盖率不低于50%，才算该事实通过；绑定的全部事实都通过才记为证据承接。

有效样本、独立意图组、比较题或可归属证据不足时显示“样本不足”，不显示伪精确分数。报告同时展示原因码、置信区间、原始样本量、递进候选保留轨迹和独立探针结果。
