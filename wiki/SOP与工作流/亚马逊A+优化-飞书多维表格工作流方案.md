## 一、数据模型（三表关系）

```
┌─────────────────────────────────────┐
│         表一：ASIN 产品主表           │  ← 产品级，每个 ASIN 只写一行
│  ASIN（主键）                        │
│  商品URL / 产品名称 / 标题           │
│  Bullet 1-5 原版 → 优化后 1-5       │
│  核心卖点 / A+共用模块方案（一/二/六）│
│  目标受众 / 优化方向 / 热销码        │
│  AI 分析（飞书原生AI小组件）         │
│  任务状态 / 负责人                   │
└────────┬──────────────┬─────────────┘
         │ link         │ link
         ↓              ↓
┌─────────────────┐  ┌─────────────────────────┐
│ 表二：SKU 变体表  │  │   表三：竞品跟踪表          │
│ SKU_ID（主键）    │  │   竞品ASIN（主键）          │
│ ○ 关联 ASIN      │  │   ○ 关联我方ASIN           │
│   变体名称        │  │   竞品商品URL / 产品名称     │
│   变体主图URL     │  │   竞品主图截图 ✨            │
│   变体主图截图 ✨   │  │   竞品A+截图 ✨             │
│   A+页面截图 ✨    │  │   竞品分析评语              │
│   是否重点推广     │  │   采集时间                  │
│   做图风格         │  └─────────────────────────┘
│   模块三/四/五提示词│
│   素材清单 / 出图状态│
└─────────────────┘
```

> [!tip] 飞书实现方式
> - **关联字段**：子表新建「link」类型字段 → 指向主表，单向关联
> - **引用字段**（待建）：基于关联字段，新建 lookup 类型字段拉取主表列
> - 引用字段只读，数据实时同步主表，无需手动维护

## 五、自动化流程

```
【表一触发】商品 URL 填入
  ↓
  解析 ASIN → 抓取 Amazon 数据 → 回填 A 区
  ↓
  DeepSeek API (Prompt①) → 回填核心卖点 + 优化后 Bullet
  ↓
  DeepSeek API (Prompt②) → 回填 A+共用模块方案（模块一/二/六）
  ↓
  自动在表二批量创建 SKU 记录（每个颜色变体一行）
  → 关联 ASIN，填入变体名称 + 变体主图 URL
  ↓
  状态 → "待审核"，飞书通知负责人

【表二触发】「是否重点推广」勾选
  ↓
  DeepSeek API (Prompt③) → 回填做图风格
  ↓
  DeepSeek API (Prompt④) → 回填模块三/四/五提示词 + 素材清单
  ↓
  出图状态 → "已生成"
```

> [!tip] AI 调用实现方式
> 通过飞书字段捷径（aily 工作流 / FaaS 版）调用 DeepSeek API。
> 详见 [[飞书字段捷径-DeepSeek-AI分析方案]]，文件路径：`02-AI工程/飞书字段捷径-DeepSeek-AI分析方案.md`

> [!tip] 触发解耦的好处
> 表一和表二的自动化独立触发：
> - 表一：URL 填入即开始，不等变体确认
> - 表二：勾选「是否重点推广」才出图，避免所有变体都跑一遍 AI 浪费额度
