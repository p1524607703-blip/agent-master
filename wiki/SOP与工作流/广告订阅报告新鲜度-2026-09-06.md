## 为什么首轮 5/5 全挂（脚本 bug，已修复）

`download_ad_reports.js` 的跳过逻辑原本是「目标文件存在就跳过」：

```js
if (fs.existsSync(targetPath) && !overwrite) { 跳过 }
```

报告文件名是固定的（如 `广告活动 30D 日期.csv`），且这批 CSV **不会被下游消费删除**。于是 09-04 那次下载落盘后，此后每次运行都命中「已存在」直接跳过 —— 磁盘上永远躺着同一份旧快照，新鲜度校验必然天天失败，然后天天白等两轮 20 分钟。

已改为按 mtime 新鲜度判定（新增 `skipIfFreshHours`，默认 20 小时）：当天新下载的才跳过，隔天的一律重下。

## 为什么 CPO 报告救不回来（需人工介入）

两轮重下均报 `找不到报告: 川鹏推广的商品 每日CPO单双计算`。

写滚动探针把 ag-grid 列表滚到底复验，排除「虚拟化只渲染可见行」的可能，实际订阅列表共 11 个报告：

```
受众 30D 日期 / 达成转化的商品 30D 日期 / 周/月已购买产品-（手动修改时间）7月
广告位 30D 日期 / 周/月广告成本-（手动修改时间）7月 / 广告活动 30D 日期
小时级广告活动 7天成熟归因 每日 / 推广的商品 30D 日期 / S81广告位 30D 日期-搜索词词-每日
投放 30D 日期 / 搜索词 30D 日期
```

**没有任何含「CPO」的报告。** 该订阅已不在列表中。

可能原因（按可能性排序）：
1. **订阅被删除或改名** —— 有人在后台删了这条订阅，或改成了别的名字。
2. **订阅过期被 Amazon 清理** —— 长时间未再运行的订阅报告会被清理。
3. 报告挂在别的标签页/筛选视图下，当前 `advertising.amazon.com/reporting` 默认视图看不到。

建议人工操作：登录川鹏2号广告后台 → 报告中心 → 重新订阅 CPO 相关报告（或直接确认是否还有必要保留）。**修复期间 `config-chuanpeng.json` 不建议删除这条配置**，否则以后没有失败信号会静默丢数据。

## 附带观察

搜索词 30D 报告中 `2026-09-06` 只有 15,556 行，比前几日（20,419~21,742）少约 26%。这是搜索词归因延迟的典型形态 —— 最新一天的行数会在后续一两天回填增长。看趋势时不要把最新一天当完整数据。
