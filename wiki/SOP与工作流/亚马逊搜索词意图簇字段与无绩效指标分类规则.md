# 亚马逊搜索词意图簇字段与无绩效指标分类规则

> [!summary] 摘要
> 不使用 ACOS、CVR、订单量等绩效指标时，仍可依据搜索词语义、商品域、产品类型、用户任务和页面/行为证据建立“语义意图簇”。这种分类适合做搜索词理解、广告结构迁移和 Listing 承接检查，但不能单独判断商业价值，也不能仅凭语义决定放大或因低效而否定。

## 核心知识

### 一、结论：可以分类，但只能得到语义簇

这套字段足以回答：

- 用户在找什么产品；
- 给谁、在何处、为了什么任务使用；
- 需要哪些功能、能力和身体适配条件；
- 搜索词应归入哪个语义任务簇；
- 与当前广告商品是否明显相关或明显错配。

它不能在没有绩效数据时回答：

- 该意图是否值得加预算或提高竞价；
- 该词是否具有稳定转化价值；
- 某个意图簇是否比另一个意图簇更盈利；
- 语义相关的词是否应该因为低效被否定。

因此必须区分：

```text
语义意图簇 = 用户想完成什么任务
运营价值簇 = 这个任务是否值得投入预算
```

前者可不看绩效指标；后者必须结合曝光、点击、订单、CVR、ACOS、NTB、利润和样本量。

### 二、字段应分成四层

| 层级 | 字段 | 用途 |
|---|---|---|
| 领域门控层 | `primary_domain`、`secondary_domain`、`product_type` | 先判断是否属于当前商品世界，阻止同词异义和错品类混入 |
| 意图槽位层 | `audience_intent`、`function_intent`、`capability_intent`、`event_intent`、`location_intent`、`body_need_intent`、`time_intent`、`substitute_intent`、`complement_intent` | 从搜索词中提取显式条件与合理推断条件 |
| 推理结果层 | `latent_task`、`intent_stage`、`evidence_type`、`confidence_level`、`intent_cluster` | 将多个槽位组合成完整购物任务，并标注证据强度 |
| 决策层 | `routing_action` | 将结果流转到广告结构或审核队列，但不在无绩效数据时直接做商业放大决策 |

> [!warning] 不要把输出字段再次当作原始证据
> `latent_task`、`intent_cluster`、`confidence_level` 和 `routing_action` 都是模型推理结果。它们可以用于过滤和复核，但不能反过来证明搜索词本身具有该意图。

### 三、无绩效指标分类流程

```text
搜索词标准化
→ 商品域与产品类型门控
→ 显式槽位提取
→ 否定词、比较词与条件冲突检查
→ 有证据的隐含槽位推断
→ 生成 latent_task
→ 按“同一用户任务”形成 intent_cluster
→ 标注 evidence_type 与 confidence_level
→ 执行语义 routing_action
```

#### 1. 搜索词标准化

- 统一单复数、拼写变体和同义词，如 `loafers`、`slip-ons`、`boat shoes`；
- 保留品牌、否定、比较、预算和约束词；
- 不把长尾词简单拆成互不相关的单词，必须保留词间关系。

#### 2. 领域和产品门控

优先判断 `primary_domain` 与 `product_type`。如果产品类型与广告 ASIN 明显不兼容，则进入错配审核，不继续用场景相似性强行归簇。

例如：

```text
water shoes for rocky river
```

与水鞋商品高度相关；而：

```text
waterproof shoe covers for gardening
```

虽然包含 `water` 和 `shoe`，产品类型却是鞋套，不应归入水鞋意图簇。

#### 3. 显式槽位优先

搜索词直接出现的内容标记为 `explicit`。未出现的槽位保持空值，不为填满字段而推断。

```text
mens wide toe box slip on shoes for standing all day
```

可直接得到：

- `product_type`: slip_on_shoes
- `audience_intent`: men
- `body_need_intent`: wide_toe_box
- `event_intent`: standing_all_day
- `function_intent`: long_wear_comfort

其中“需要缓震、足弓支撑”只能视为可能需求，不能自动当作显式条件。

#### 4. 由槽位生成潜在任务

`latent_task` 应采用统一模板：

```text
[使用者] 在 [场景/地点/时间] 为了 [任务]
需要 [产品类型] 具备 [功能/能力/身体适配条件]
```

示例：

> 男性宽脚用户需要一双前掌不挤脚、适合长时间站立的休闲一脚蹬鞋。

#### 5. 按任务聚类，而不是按词根聚类

以下词面相似，但任务不同，应拆成不同意图簇：

```text
water shoes for river hiking
water shoes for gym shower
```

建议簇结构：

```text
product_type
→ latent_task
→ audience/body_need
→ event/location/function 修饰条件
```

### 四、证据与置信度规则

`evidence_type` 最好按“字段”记录，而不是整条搜索词只记录一个值。一条词可能同时含有显式和推断信息。

| 证据类型 | 可使用的证据 | 无行为数据时的处理 |
|---|---|---|
| 显式 `explicit` | 搜索词直接表达 | 可直接标注，高置信 |
| 页面验证 `page_validated` | 广告商品标题、规格、Bullet、A+ 明确支持 | 可标注，但要记录证据位置 |
| 行为验证 `behavior_validated` | 点击 ASIN、购买 ASIN、搜索改写、共购等支持推断 | 没有这些字段时必须为空，不得伪造 |
| 常识推断 `inferred` | 场景通常隐含的需求 | 可标注，但与显式条件分开，通常为中或低置信 |

置信度建议采用规则等级，不输出伪精确概率：

- **高**：产品类型明确，核心任务由多个显式槽位支持，且不存在冲突；
- **中**：产品类型明确，但核心任务含一个关键常识推断，或存在轻微歧义；
- **低**：产品类型含糊、任务主要依赖推断、可能跨多个商品域或存在条件冲突。

### 五、无绩效数据时 routing_action 的安全边界

无绩效指标时，`routing_action` 应改成“语义流转”，而不是“预算决策”。

| 动作 | 允许条件 |
|---|---|
| `cluster_route` | 语义明确，迁移到对应意图簇等待绩效验证 |
| `listing_gap_review` | 搜索意图相关，但商品页面缺乏明确承接证据 |
| `ambiguity_review` | 多义词、跨域词或任务不完整，需人工审核 |
| `semantic_negative_candidate` | 产品类型、受众或任务与广告 ASIN 明显冲突，可列为语义否定候选 |
| `performance_observation` | 语义相关但价值未知，保留并等待绩效数据 |

以下动作不能只靠语义执行：

- `scale_up` / 放大预算；
- `bid_up` / 提高竞价；
- 因“表现差”直接否定；
- 因模型给出高置信就转入 Exact 收割。

### 六、建议补充的字段

现有字段能覆盖核心任务，但为减少误判，建议补充：

| 字段 | 作用 |
|---|---|
| `brand_intent` | 区分品牌收割、竞品替代和无品牌需求 |
| `price_intent` | 记录 `under $40`、`cheap`、`premium` 等预算约束 |
| `style_material_intent` | 记录 canvas、leather、retro、dress casual 等款式和材质 |
| `negation_exclusion` | 记录 `not leather`、`without arch support` 等排除条件 |
| `ambiguity_flags` | 标记多义词、跨域、条件冲突和信息不足 |
| `asin_fit` | 当前广告商品对该意图的承接程度：满足、部分满足、不满足、未知 |
| `field_evidence` | 按字段保存证据类型和原文片段，避免整词单一证据标签失真 |

### 七、过滤规则

建议依次使用三道过滤器：

1. **相关性硬门控**：`primary_domain + product_type + asin_fit`；
2. **任务聚类**：`latent_task + event/location/body/function`；
3. **证据门控**：`field_evidence + confidence_level + ambiguity_flags`。

只有第一道门控明确不匹配时，才可在无绩效数据下列为语义否定候选。第二、三道过滤器用于分簇与审核，不用于判断商业价值。
