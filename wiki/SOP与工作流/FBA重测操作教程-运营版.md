# FBA 尺寸/重量重测操作教程（运营版）

> [!summary] 摘要
> 面向运营人员的 FBA 尺寸与重量重测操作教程，说明准备工作、申请步骤与人工确认要求。

> 适用范围：需要在「紫鸟浏览器」里批量重测 Amazon FBA 商品的尺寸/重量，向亚马逊申请退还多扣的配送费。
> 本文面向运营同学，按步骤操作即可，**无需懂代码**。

---

## 一、这是什么，为什么要做

亚马逊在入仓时会用机器称重/量尺寸，并据此收 FBA 配送费。如果它测出来的尺寸、重量**比实物大**，你就会**被多扣钱**。

「FBA 重测（remeasure）」就是向亚马逊申请重新测量。测准之后，多收的费用会退还，后续按真实尺寸计费。

> 一句话：尺寸重量测大了 → 申请重测 → 退差价。本教程教你用本地控制台**安全、批量**地发起重测，且**每一步都由你人工确认提交**，不会误触。

---

## 二、第一次使用前：准备（只需做一次）

### 1. 紫鸟浏览器已登录目标店铺
- 打开紫鸟浏览器，确认目标 Amazon 店铺（如「川鹏2号」）已登录、能正常打开 Seller Central。
- **重测过程中紫鸟浏览器窗口必须保持打开、不能关、不能最小化到退出**。这是工具运行的"手和眼睛"。

### 2. 紫鸟 CLI 已授权（技术同学或你自己确认一次）
在终端执行：
```bash
ziniao-cli doctor
```
要求看到 **config / API Key / ZClaw Bridge / 客户端登录 全部 ✓**。
若未授权，先跑一次：
```bash
ziniao-cli config init --new
```
按提示完成授权后再继续。

### 3. 如果你本机开了 Surge / 系统代理（很重要）
紫鸟浏览器必须走紫鸟自己的网络通道，不能被强制直连本机 IP，否则亚马逊会风控、连不上。
- 打开 Surge 配置，在 Amazon 的 `DIRECT` 规则**之前**加一条：
```
PROCESS-NAME,ziniaobrowser,DIRECT
```
- 不确定怎么加，找技术同学帮你看一眼。

### 4. 启动本地控制台
在终端进入控制台目录并启动（技术同学会给你这个目录）：
```bash
cd <控制台目录>
bash start.sh
# 或： node server.js
```
看到提示监听 `8787` 即成功。关掉终端窗口也没关系，`start.sh` 是后台常驻的。

### 5. 打开操作页面
浏览器访问：**http://127.0.0.1:8787/**
看到「准备列表 / 完成列表 / 开始·暂停」面板即正常。

## 三、每次重测：操作步骤

### 第 1 步：加入要重测的 SKU
- **单个**：在输入框里粘贴一个 FNSKU（如 `X0025S900H`），回车加入。
- **批量**：点「批量加入」，把一串 FNSKU 粘进去（自动识别 `X` 开头 10 位的编码，大小写不限），确认后一次性进准备列表。

### 第 2 步：设置两个默认选项（对所有 SKU 生效）
- **原因**：一般选「重新测量和赔偿亚马逊物流配送费用」。
- **包装**：自有包装一般选「否」。
> 这两项会套用到本次所有 SKU，不用每个单独选。

### 第 3 步：选调速档位（防封控）
| 档位 | SKU 间隔 | 适用场景 |
|------|----------|----------|
| 保守 | 20–40 秒 | 大量（≥50）/ 长期盲跑，最稳 |
| 均衡（默认） | 中等 | 一般日常，<20 个 |
| 激进 | 5–10 秒 | 仅少量测试，**有封控风险，不建议批量** |

选完**立即生效**，对下一个 SKU 就开始用新节奏。

### 第 4 步：点「开始」
控制台会**逐个 SKU**自动：
1. 在紫鸟浏览器打开重测页 → 填入 FNSKU → 选原因/包装 → 一路推进
2. **推进到「继续」按钮前自动停下**（硬停），**绝不自动点提交**

### 第 5 步：你去紫鸟浏览器人工提交
当某个 SKU 停在「继续」前：
1. 切到紫鸟浏览器，核对自动填好的信息（FNSKU、原因、尺寸重量）是否正确
2. **确认无误后，你手动点「继续」** 提交给亚马逊
3. 提交完成后，该 SKU 自动进入「完成列表」

### 第 6 步：暂停 / 恢复
- 想停：点「暂停」，会在**当前步骤边界**停下，当前 SKU 退回准备列表队首，下次从它重跑（不会重复提交已提交的）。
- 想继续：再点「开始」即可。

## 四、安全须知（必读，避免封号）

- **绝不自动提交**：工具最高优先级规则就是"看到继续按钮就停"，提交动作只能由你在紫鸟浏览器里手动点。
- **保持节奏**：同一店铺短时间密集提交容易被风控，请用「均衡」或「保守」档，别长期开「激进」。
- **紫鸟窗口别关**：关了工具就"失明"，重测会失败。
- **不回传任何机密**：工具只记录状态和不敏感的页面文本，不碰你的 Cookie / 令牌 / 账号密码。

## 五、常见异常和处理

### 1. 提示"页面结构与已知 FBA 重测流程不一致"
- **多数情况**：紫鸟向导页面还没渲染完，工具第一次读取时页面是空的/半成品。
- **处理**：工具已内置"等几秒重试"，通常会自己过。若仍报错，手动刷新紫鸟那个标签页，把该 SKU 重新加入准备列表再跑一次。
- **少数情况**：亚马逊真的回了"找不到该商品 / 无库存 / 不符合重测条件"的页面。这种是真的不能重测，人工看一下页面提示即可。

### 2. 打开 http://127.0.0.1:8787/ 没反应
- 控制台可能没在跑（会话回收/重启过）。回到**第二节第 4 步**重跑 `bash start.sh` 即可。

### 3. 提示"无法解析店铺标签页 targetId"
- 紫鸟浏览器没开 / 店铺没登录 / CLI 没授权。检查第二节第 1、2 步。

### 4. 紫鸟浏览器打不开亚马逊页面（连接被重置）
- 多半是代理问题。检查第二节第 3 步的 Surge 规则是否加好。

## 六、换店铺 / 找技术支持

- **换店铺**：技术同学在启动控制台前设置店铺环境变量（`ZINIAO_STORE_ID` / `ZINIAO_STORE_NAME`）即可，你不用改任何东西。
- **不会用 / 报错搞不定**：把错误提示截图发给技术同学（或负责这个控制台的人），不要自己在紫鸟里乱点提交。

---

> 本教程对应本地控制台 `ziniao-fba-controller`。控制台核心原则：**自动推进、人工提交、随时可暂停**。照上面步骤来，既快又不会误触封号。
