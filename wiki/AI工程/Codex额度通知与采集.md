# Codex额度通知与采集

> [!summary] 摘要
> 额度变化通知优先触发可信读取，主设备本地用量与子设备服务端计量也触发复核，60秒定时读取兜底。设备 Token 独立计量，并发额度按同期新增 Token 估算分摊，始终保留待归属与误差边界。

## 核心知识

- 官方通知只作提示，每次通过主动读取重新核验源账户和实际额度，不直接信任通知载荷。
- 主设备每2秒检查新增用量事件；子设备完成计量后通过数据库通知和既有 SSH 私有通道唤醒采集器。提示不含凭据、聊天内容或设备 Key。
- 合并1秒内的事件，官方读取最短间隔5秒；活动后约15秒追加核验，空闲时60秒兜底。页面可见时每15秒刷新。这些均为本系统调度参数，不是 OpenAI 更新承诺。
- 独立采集进程未必能收到其他客户端的全部官方通知，因此不能撤掉主动读取兜底。通知通道断开自动退避重连，定时读取仍工作。
- 重新上传主机用量时不修改旧额度的实际采集时间。失效数据不显示成最新。原账户认证、主窗口及会话数据库保持原运行方式。
- 具体 Token 与官方额度百分比独立。并发占比为估算，不能据此推算套餐总 Token 或账单费用。
- rc.9 为新增额度建立暂估批次，邻近30分钟的增量共享观察组；迟到计量按原请求时间进入对应组，自动修订批次，不需要官方额度再次增长。
- 本人确认与升级前结算保留。未知计量、身份或采集缺口继续待归属。观察后估算仍可因更晚补账修订，不把30分钟解释成官方延迟上限。
- 私有SQLite保存请求时间、模型、Token与观察组修订，JSON只保存紧凑摘要。每个事件只归一个组，重复响应补账不重复计数。管理页面可以查看批次修订前后金额。
