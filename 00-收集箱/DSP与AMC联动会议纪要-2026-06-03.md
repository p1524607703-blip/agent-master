# DSP 与 AMC 联动会议纪要

> 来源：2026年06月03日 14点37分.m4a  
> 转写文件：`00-收集箱/2026-06-03-2026年06月03日 14点37分.txt`  
> 整理时间：2026-06-03  
> 说明：音频转写存在少量识别误差，本文已按上下文将 DST/DHP 等误识别统一理解为 DSP，将 SA 理解为 Sponsored Ads，AMC 理解为 Amazon Marketing Cloud。

## 一、会议核心结论

本次会议不是单纯介绍 DSP，而是在讨论：公司是否应该重新尝试 DSP，以及如何让 DSP、站内 Sponsored Ads 和 AMC 形成可衡量、可协同的投放体系。

核心判断是：

- DSP 不应被当作单独的“展示广告渠道”，而应被定位为站内广告之外的主动触达与人群经营工具。
- DSP 的价值不只在直接 ACOS，而在于把潜在人群推进到 PDP 浏览、加购、搜索、站内点击等后续动作。
- 后续如果投 DSP，不能只看最后归因 ACOS，需要用 AMC 看路径、重合度、人群包承接和后续 Sponsored Ads 表现。
- 对 WHITIN 这类产品线复杂、定位特殊的品牌，DSP 人群不能只用大类目泛投，必须围绕具体产品线、竞品 ASIN 池、目标 ASIN 池来拆分。
- 最值得先做的是 Consideration 和 Conversion 两段：竞品/类目高意向人群拉新，以及浏览、点击、加购、视频触达后的再营销。

## 二、DSP 与 SD / Sponsored Ads 的关系

会议中反复强调，DSP 与 SD 都属于展示型触达，但能力边界不同。

| 维度 | SD / 站内展示广告 | DSP |
|---|---|---|
| 触达范围 | 主要在 Amazon 站内 | Amazon 站内、站外媒体、设备、流媒体等 |
| 投放逻辑 | 更接近站内广告扩展 | 主动型、全漏斗、跨渠道触达 |
| 人群排除 | 能力较有限 | 可以更细地排除购买人群、竞品购买人群等 |
| 数据维度 | 通常偏广告活动效果 | 可结合 AMC 看路径、频次、人群标签、转化链路 |
| 适合目标 | 站内再营销、商品投放 | 拉新、竞品抢夺、再营销、品牌认知、站内承接 |

我的理解：  
DSP 对我们最大的意义不是“多一个广告入口”，而是多了一套主动制造和筛选人群的能力。站内 SP/SB 是需求已经出现后的拦截，DSP 是在用户还没来搜、还没点、还没进 PDP 前先建立印象，并把这些人群导入后续站内广告承接。

## 三、为什么过去 DSP 效果不明显

会议提到公司两年前投过 DSP，投了半年到一年后停止，原因是感觉效果不明显。

这次讨论里暴露出一个关键问题：过去很可能主要用 ACOS 或直接转化来判断 DSP，这会低估展示广告的真实作用。

展示广告常见作用包括：

- 曝光后提高品牌或产品记忆；
- 用户后续搜索时更愿意点击品牌商品；
- 用户后续进入 PDP、加购或被站内广告承接；
- 被 DSP 触达过的人，在后续 SA 路径里的购买率可能更高；
- 对竞品浏览人群做主动抢夺，补足 CPC 广告抢不到的位置。

因此，后续重启 DSP 时，不应只问“这条 DSP 活动 ACOS 多少”，更应该问：

- DSP 触达后是否提高 PDP 浏览？
- DSP 参与路径的购买率是否高于纯 SA 路径？
- DSP 人群推给 SA 后，站内广告 CTR、CVR、CPC、转化是否更好？
- 频次到多少次后转化最高，什么时候开始疲劳？

## 四、DSP 可以服务的几类人群

### 1. 竞品 ASIN 浏览人群

服务方建议竞品定义优先做到 ASIN 层级，而不是只做品牌层级。

原因是品牌层级人群太大、太杂，容易包含大量无关流量。对鞋类产品来说，应该按产品线建立竞品 ASIN 池，例如某一类 barefoot shoes、water shoes、wide sneakers 等。

适合打法：

- 把竞品相似 ASIN 加入竞品池；
- 圈定过去 30/90 天浏览竞品但未购买竞品或本品牌的人；
- 用 DSP 或 AMC Audience 做抢夺；
- 创意强调差异点：宽鞋头、舒适度、zero drop、防滑、轻量、价格优势、场景适配。

### 2. 本品牌浏览未购买人群

这是最接近转化的一类人群。DSP 相比 SD 的优势在于可以更精细地排除购买者，避免重复打已经买过的人。

适合打法：

- PDP 浏览未购买；
- 多次 PDP 浏览未购买；
- 加购未购买；
- 广告点击未购买；
- 视频触达或 DSP 曝光后未购买。

### 3. DSP 触达后推给站内广告的人群

会议中明确讨论了一个关键联动：DSP 触达或点击过的人，可以通过 AMC 打包成人群，再推送给站内 Sponsored Ads 做出价加权。

这个逻辑很重要：

DSP 负责主动触达和预热，Sponsored Ads 负责用户搜索或进入站内后的承接。

典型链路：

DSP 曝光 / 点击 → AMC 打包人群 → 推送到 Sponsored Ads → 用户搜索关键词时提高出价或定向触达 → 完成转化。

我的判断：  
这正好对应我们现在做的 Hermes + AMC Audience SQL 工坊。网页端 SQL 模板不只是“生成 SQL”，它应该成为运营把 DSP/SA 人群联动落地的工具。

### 4. 搜索词、点击、加购等 AMC 自定义人群

会议中提到，AMC 可以用于把很多更细的人群包做出来，例如：

- 搜索过某类关键词的人；
- 被某些广告曝光过但未购买的人；
- 点击过 SP/SB/DSP 但未购买的人；
- 加购但未购买的人；
- 促销期购买人群；
- DSP 点击/曝光人群；
- Lookalike / 相似受众。

这些都是广告后台自带受众无法完全覆盖的部分，也是自定义受众存在的意义。

## 五、AMC 在这个体系里的角色

AMC 的角色不是“报表工具”这么简单，而是三件事：

1. 数据诊断：看路径、频次、重合度、转化时间、人群画像。
2. 受众生产：把浏览、点击、加购、视频触达、购买排除等行为转成 Audience。
3. 协同桥梁：让 DSP 触达的人群可以被 Sponsored Ads 承接。

会议里也提到，基础 AMC 能看到广告触达相关数据；如果要看到更完整的非广告自然行为、人群画像或更广泛数据，可能涉及 Amazon 的付费数据集，例如 ASI / FSI / ESI 一类数据。

我的判断：  
当前阶段不必一开始追求付费数据集。先把已有广告触达数据用好，把 DSP、SA、AMC 的基础闭环跑起来，价值会更直接。

## 六、投放策略框架

服务方把 DSP 策略大致放在四个漏斗阶段：

- Awareness：品牌认知；
- Consideration：兴趣与考虑；
- Conversion：转化；
- Loyalty：复购与老客。

但会议中也明确，目前更适合先从 Consideration 和 Conversion 开始。

建议优先级：

| 优先级 | 策略 | 说明 |
|---|---|---|
| P0 | 本品牌 PDP 浏览未购买 | 最接近转化，适合先验证 |
| P0 | 竞品 ASIN 浏览未购买 | 用于抢夺竞品高意向流量 |
| P1 | DSP 视频/曝光/点击未购买 | 做站内广告承接和再营销 |
| P1 | 加购未购买 | 需要强转化素材、优惠、coupon |
| P2 | 类目/兴趣/生活方式人群 | 适合扩量，但需要产品线精细化 |
| P2 | Lookalike / 相似受众 | 等种子人群质量稳定后再扩 |

## 七、素材策略

会议中讨论了商品主图素材和自定义素材的区别。

服务方观点：

- 商品型素材适合转化阶段，因为有价格、评价、促销等信息；
- 自定义素材更适合中上层漏斗，用于传递品牌、场景、卖点和视觉记忆；
- 如果前期素材不足，可以先用商品型素材跑起来，但后续应准备更有场景感的自定义素材。

我的判断：  
WHITIN 的产品卖点比较依赖场景和脚感理解，例如宽鞋头、zero drop、轻量、防滑、涉水、舒适通勤等。只用白底主图很难解释差异。DSP 如果要做上层或竞品抢夺，素材必须比站内主图更会讲“为什么选我”。

## 八、预算建议

会议中服务方提到：

- 每个策略日预算建议不要低于 30 美金；
- 如果按多个策略同时铺开，月预算大约会到 1 万美金左右；
- 具体预算还要根据最终 ASIN 池和产品线拆分来推。

我的判断：  
如果公司是重新试 DSP，不建议一开始铺太多策略，否则预算被切碎，数据无法判断。更稳的方式是：

1. 先选 1-2 条产品线；
2. 每条产品线只跑 2-3 个核心策略；
3. 每个策略预算保证可学习；
4. 两周看前置信号，一个月看路径与承接效果。

## 九、后台操作与组织协同

会议后半段看了 DSP 后台。

DSP 后台结构大致是：

- Campaign / 广告活动；
- Order / 策略或订单层；
- Line item / 更细的投放单元；
- 设备端、版位、素材、出价、报告维度。

相比 Sponsored Ads 的“Campaign → Ad Group → Keyword / Targeting”，DSP 的结构更偏媒体投放系统，维度更多，包括设备端、站内站外、素材类型、端口表现等。

会议中也提到，如果后续公司决定自己投 DSP，需要一段学习和权限开放过程。服务方可以先代理或协助一段时间，让内部团队看后台、学数据、逐步接手。

我的判断：  
公司真正想要的是把 DSP 能力内化，而不是完全外包。原因是产品理解、ASIN 选择、竞品定义和站内承接都需要内部运营深度参与。外部服务方可以提供方法和后台经验，但策略迭代最好由内部掌握。

## 十、对当前 Hermes / AMC 项目的启发

这场会议直接验证了我们当前项目方向是对的，但也提出了更明确的边界。

### 1. Hermes 应该做分析，不做网页修改

Hermes 的核心任务应是：

- 自动读取 AMC 查询结果；
- 清洗上万行搜索词、路径、受众、广告表现数据；
- 分析哪些受众包值得建；
- 解释路径和投放建议；
- 产出给运营可复制、可执行的结论。

网页 UI 和 SQL 模板仍由我们维护，不应让 Hermes 直接改页面。

### 2. SQL 工坊要围绕成功 SQL 沉淀模板

会议后我们已经有两个跑通案例：

- PDP 浏览未购买；
- 视频播放进度未购买。

后续所有模板都应该按“已跑通 SQL → 模板化 → 参数化 → 页面一键复制”的流程推进，而不是凭空写理论 SQL。

### 3. 受众包推荐 TOP 榜有必要

会议中多次出现“人群太多，不知道先投哪个”的问题。  
因此可视化仪表盘应提供一个受众候选包 TOP 榜，按以下维度排序：

- 是否能直接建 Audience；
- 是否已有成功 SQL；
- 人群意图强度；
- 是否可被站内广告承接；
- 预计漏斗位置；
- 是否需要 DSP；
- 是否需要购买排除池；
- 数据是否足够。

## 十二、开放问题

1. 首批试投到底选哪条产品线：water shoes、barefoot shoes、men sneakers，还是其他？
2. 每条产品线的目标 ASIN 池和购买排除 ASIN 池分别是什么？
3. 竞品 ASIN 池由谁维护，是否按产品线拆分？
4. DSP 人群包推送到 Sponsored Ads 后，后台是否能稳定选择和使用？
5. 当前 AMC instance 是否已经接入 DSP 与 Sponsored Ads 数据？
6. 是否需要开通 Amazon Ads API / AMC API 来让 Hermes 自动拉取数据？
7. 是否允许服务方先代理投放并开放只读后台给内部学习？
8. 最小试投预算是多少，能否保证每个策略日预算不低于 30 美金？

## 十三、我的最终判断

这场会议真正的主线是：公司正在从“只看站内广告 ACOS”的投放方式，走向“用 AMC 把人群、路径和广告协同串起来”的方式。

DSP 本身不是答案。答案是：

DSP 负责主动触达和制造高意向人群；  
AMC 负责识别、解释、打包这些人群；  
Sponsored Ads 负责在用户有搜索和购买动作时完成承接；  
Hermes 负责把复杂数据分析成运营能执行的建议；  
SQL 工坊负责把这些建议变成可复制、可验证、可复用的 Audience 模板。

如果按这个方向做，DSP 不再是一个“试试看有没有 ACOS”的孤立渠道，而会变成整个亚马逊广告系统的人群发动机。
