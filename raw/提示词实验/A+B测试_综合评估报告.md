# A+B 测试评估报告

> 测试目标：对比「飞书链接传递提示词」与「完整文本复制传递提示词」对同一 ASIN 的输出差异
> 测试 ASIN：B0FZB6D2R4（WHITIN Wide Barefoot Shoes for Kids）
> 测试时间：2026-04-28

---

## 一、实验环境与约束

| 维度 | Agent A（链接） | Agent B（文本） |
|---|---|---|
| 提示词获取方式 | 飞书文档链接 | 完整提示词文本直接粘贴 |
| 提示词内容来源 | 同一份 V4 文档 | 同一份 V4 文档（实时抓取后复制） |
| 执行环境 | Task Agent（search 类型） | Task Agent（search 类型） |
| Amazon 访问能力 | ❌ 无（无浏览器工具） | ❌ 无 |
| 差评数据来源 | 无（只能行业推断） | 无（只能行业推断） |
| ASIN 产品信息 | 来自 WebReference + 本地已有文件 | 来自 WebReference + 提示词内嵌 |

### 关键约束说明

1. **两个 Agent 均无法真实访问 Amazon 页面**，产品信息来自 WebReference（在系统提醒中提供）
2. **都没有真实的差评/退货数据**，痛点分析均基于行业推断
3. **Agent A 无法直接访问飞书链接**，但成功读取了本地 Obisidian 中已有的 A+ 相关文件作为补充输入
4. **用户第 7 条要求「忽略标题<15和<20字」** —V4 文档中该约束已被修改为 50/60 字符，此处按实际忽略

## 四、偏离原因分析

### 4.1 结构性偏离（Agent A 输出不完整）

**直接原因**：Agent A 作为 Task Agent 类型，缺少完整的提示词工作流约束。飞书链接无法直接访问 → 退而求其次读本地文件 → 但本地文件是补充预览版而非完整 V4 → 缺少模块二至五和转化检查的执行指令。

**根因**：链接传递方式在 Agent 无法直接访问外部 URL 时退化为「零提示词」，Agent 只能基于本地残存知识生成。

### 4.2 观点性偏离（Agent A 推理更策略化）

**现象**：Agent A 的痛点推理是「家长无法验证孩子穿着感受」，这是一个**元认知层面**的痛点（关于验证本身的焦虑），而 Agent B 的痛点是「尺码偏大 40%/耐用性 25%/鞋底薄 15%」，是**数据驱动**的具体问题。

**原因**：
- Agent A 没有完整的差评分析格式约束 → 转向更深层次的产品策略推理
- Agent A 读取了本地「品类知识锚点」文件 → 获得了额外的策略视角（「儿童鞋 → 父母决策逻辑」）
- Agent B 有明确的「来源标注」格式要求 → 必须按格式输出，限制了自由推理空间

### 4.3 场景差异性

**现象**：Agent A 的 Hero 场景 A 选了「操场晨跑」、Agent B 选了「草坪夕阳奔跑」。

**原因**：Agent A 读取的本地文件中有「学校操场/公园草地」的童鞋场景锚定规则，而 Agent B 从完整提示词的「推理结论 2」推导出 4 个场景后，按其叙事逻辑选择了最能表达品牌调性的那个。

## 五、综合结论

### 5.1 核心发现

| 结论 | 说明 |
|---|---|
| **链接传递在不可达时退化为零** | 当 Agent 无法访问飞书链接时，Agent A 只能依赖本地缓存 → 输出降级。这不是提示词质量问题，是分发机制问题 |
| **完整文本传递保证一致性** | Agent B 按提示词工作流严格输出，完整度 100%，格式规范，可预测性强 |
| **链接失败时 Agent A 推理更深但不完整** | Agent A 的场景推理质量实际上高于 Agent B（5 场景对比表 + A/B Test 建议），但因为丢失后续模块执行指令而中断 |
| **本地缓存文件产生了「知识污染」** | Agent A 读取了本地补充预览文件后，输出的部分内容（如品类知识锚点的引用）超出了 V4 本身的约束范围 |

### 5.2 提示词分发建议

| 场景 | 推荐方式 |
|---|---|
| 人工复制粘贴使用 | **完整文本** — 100% 可控 |
| 通过 Agent 链自动调用 | **完整文本** — 避免链接不可达降级 |
| 飞书链接作为分发给人类的入口 | ✅ 可用 — 但 Agent 使用时需先 fetch 获取文本再执行 |
| 需要快速迭代提示词（飞书在线改） | 链接 + 加一步 `lark-cli docs +fetch` 获取后再执行 |

### 5.3 V4 自身的问题发现

| 问题 | 证据 |
|---|---|
| **差评分析格式约束太强导致 B 输出看起来像模板** | Agent B 的痛点输出精准但缺乏 Agent A 那种元认知层面的策略洞察 |
| **模块一的场景选择引导在 B 中被严格执行但未等待真正用户交互** | B 模拟确认后直接生成全方案，但这是 Agent 限制而非提示词问题 |
| **标题字符限制被修改为 15/20 字符（与实际 50/60 不符）** | V4 文档中有 `≤ 15字符` 和 `≤ 20 字符` 的错误值，需要修正回 50/60 |
