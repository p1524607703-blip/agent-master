# A+ 提示词补充模块预览

## 一、鞋类细分知识锚点

> 插入位置：第二步推理链——推理结论 1 之前
> 作用：给 AI 一个品类差异化提醒，防止跨品类推理漂移

```
⚠️ 品类细分注意：

推理痛点和使用场景时，必须根据鞋类细分做出差异化判断。

| 细分类型 | 特别关注的痛点方向 | 视觉/文案注意 |
|---|---|---|
| 赤足/宽鞋头/零落差 | 前掌宽度、零落差适应、尺码疑虑 | 鞋头俯视空间线，不做医学图 |
| 跑步/健走 | 轻量、透气、缓震、鞋重 | 动态步伐，网布/中底特写 |
| 工作/防滑 | 防滑边界、久站舒适、易清洁、耐磨 | 干净工作环境，外底纹路特写 |
| 户外/徒步/Trail | 抓地、耐磨、防护、地形场景 | 岩石/土路，鞋头后跟防护特写 |
| 凉拖/居家/恢复 | 脚感软、不打滑、易清洁 | 家居/浴室/沙发场景，鞋床结构 |
| 时尚/通勤 | 好搭配、有质感、通勤不累 | 全身穿搭，低饱和城市背景 |
| 儿童 | 易穿脱、安全、耐穿 | 魔术贴/拉环特写，公园/学校 |
| 水鞋/沙滩 | 快干、防滑、不闷 | 海边/泳池，明亮色调 |

如果你的推理结论没有体现该品类的特有痛点，第三步确认时主动向用户求证。
```

### 对比：赤足鞋 → V4 可能推理的痛点 vs 正确的痛点

| V4 通用推理（可能不精准） | 赤足鞋真实痛点 |
|---|---|
| 「通勤久了脚累」 | → 「前掌是否真的够宽」 |
| 「鞋子不透气」 | → 「零落差会不会难适应」 |
| 「外观不够时尚」 | → 「尺码该怎么选才不挤脚」 |

## 二、图片质量控制

> 插入位置：第四步「核心原则」之后
> 作用：防止 AI 在生图描述中出现亚马逊禁止或低效的视觉元素

```
⚠️ 图片质量控制（每个模块输出前必须逐条通过）：

1. 产品占比：PC 端 35%-60%，手机端特写可到 70%-80%
2. 产品角度：服务于模块目标（侧面/前45°/俯视/外底/后跟）
3. 文字安全区：统一留出干净空白区，方便后期加字（Post-Edit 模式）
4. 不要渲染英文文案到图内，MDD由设计师后期添加

生图描述中禁止出现以下内容：
┌─────────────────────────────────────────────┐
│ ✗ 底部缩略条 / 多余产品罗列                      │
│ ✗ 假认证标志 / 假 logo / 假吊牌 / 假包装盒       │
│ ✗ QR 码 / 网址 / 折扣标签                        │
│ ✗ before/after 医疗对比图                        │
│ ✗ AI 生成的乱码假文字                             │
│ ✗ 扭曲鞋头 / 改变外底纹路 / 改变 logo 位置         │
│ ✗ 未证实的科技名称 / 系列名称                     │
│ ✗ eco-friendly / sustainable 标志（除非有证据）    │
└─────────────────────────────────────────────┘

英文文案注意（写进建议文案的用词约束，不是生图约束）：
- 禁止：best、guarantee、guaranteed comfort、pain relief、cure、treat、
  eco-friendly、clinically proven、laboratory tested（除非有证据）
- 可用：designed for、helps support、suitable for、cushioned feel、
  breathable feel、roomy toe box、steady traction
- 防滑 → steady traction / textured outsole（不写 guaranteed non-slip）
- 鞋楦 → roomy toe box / wide fit（不写 medical claims）
```

## 三、模块一：Hero 首图 ——替代原四宫格分割图

> 原方案：多场景四宫格分割图（4:3）
> 新方案：单一 Hero 首图 + 场景参考列表

### 设计逻辑

四宫格传达「这双鞋能去很多场景」，但对 A+ 首屏来说效率不高——买家 3 秒内无法聚焦到一双鞋的核心定位。Hero 图用 **一个最强场景 + 完整产品展示** 建立第一印象，其余的 3-5 个场景以参考列表形式提供给运营/设计师，灵活调用。

### 模块一新描述

```
- 模块一：Hero 产品定位图（PC 端 21:9 + 手机端 4:3）

  · 根据鞋类细分，选择一个最能代表该鞋核心定位的场景
  · 产品在场景中占画面 40%-55%，人物自然穿着，氛围感强
  · 文字（主标题+副标题）位于画面留白区，3 秒内传达产品定位

  场景选取规则（按鞋类细分）：
  ┌──────────────┬────────────────────────────────┐
  │ 鞋类         │ Hero 场景方向                   │
  ├──────────────┼────────────────────────────────┤
  │ 赤足/宽鞋头  │ 公园草地/林间步道，自然光       │
  │ 跑步/健走    │ 城市跑道/晨光河边，动态步伐     │
  │ 工作/防滑     │ 干净工作环境（厨房/医院走廊）   │
  │ 户外/徒步    │ 山径/岩石地面，远景山脊虚化     │
  │ 时尚/通勤    │ 咖啡馆/写字楼外，城市街景       │
  │ 儿童         │ 学校操场/公园草地，明亮活力     │
  │ 凉拖/居家    │ 沙发/木地板/泳池边，柔和光      │
  │ 水鞋/沙滩    │ 海边浅滩/泳池边，逆光通透       │
  └──────────────┴────────────────────────────────┘

  · 同时输出 3-5 个备选场景参考，供运营/设计师选择或轮换 A/B test：

  场景参考列表格式：
  场景 A（推荐）：[一句话描述] — 适合传达的核心信息：[XX]
  场景 B：[一句话描述] — 适合传达的核心信息：[XX]
  场景 C：[一句话描述] — 适合传达的核心信息：[XX]
  ...
```

### 与旧版四宫格对比

| 维度 | 旧：四宫格 4:3 | 新：Hero + 场景参考 |
|---|---|---|
| 首屏焦点 | 分散在 4 个格子 | **单一画面一击命中** |
| 叙事方式 | 四个格子拼时间线 | 一张强场景 + 列表级灵活度 |
| 制作成本 | 4 张高质量图 | 1 张 Hero + 列表供后期选 |
| 信息密度 | 每个格子信息量小 | 场景参考列表可承载更多文案 |
| 灵活性 | 固定四格 | 运营可从 3-5 个场景中挑选 |

### 注意

- Hero 图场景不要和模块三/四重复。Hero 做定位，模块三/四做变体细节
- 场景参考列表的 3-5 个场景应该覆盖推理结论 2 中的高频场景，并加入 1 个差异化场景做 A/B 对比
