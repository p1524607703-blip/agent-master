# DSP 建单页「上传 ASIN 模板报错」诊断报告

**时间**：2026-09-29 03:10 EDT（北京 15:10）
**现场**：`https://advertising.amazon.com/dsp/ENTITY1F7KI15KHQ4NT/advertisers/592097575016190071/orders/new`
（川鹏2号 / 广告主 WHITIN）
**现象**：上传 `W81_追踪商品_ASIN上传模板.csv`（116 个 ASIN）→ 红字 `Error while uploading ASINs`，
右侧显示 `No Product.`，上传区回到初始态
**结论一句话**：**不是文件的问题，是"那次上传请求本身没成功"。**

---

## 一、文件与数据：逐项排除，全部干净

| 检查项 | 实测结果 | 判定 |
|---|---|---|
| 编码 / 换行 | UTF-8 **BOM** + CRLF | ✅ 与官方模板一致 |
| 表头 | `ASIN,Featured,Domain,,*** Instructions ***` | ✅ 与刚拉取的官方模板**逐字节同构** |
| ASIN 数量 / 唯一性 | 116 条 / **重复 0 条** | ✅ |
| ASIN 格式 | 全部 10 位 `[A-Z0-9]`，异常 0 | ✅ |
| Domain 列 | 116/116 = `amazon.com`（NA 合法枚举值） | ✅ |
| 品牌归属 | 94/116 命中 `app.child_asin_mapping` → **全为 WHITIN / 父体 `B0D4DS7M7G` / 运营组 ZJ1** | ✅ 品牌没错 |
| 是否在投在卖 | 93/116 出现在《推广的商品》《达成转化的商品》；94 出现在业务报告 | ✅ 都是活商品 |
| 官方模板比对 | 从 `/dsp/rdo/api/asin-bulk-upload-file-template` 实拉（200，579 字节），表头完全一致 | ✅ 不是版本问题 |

> 唯一"不标准"之处：人工替换时把 ASIN 填到了**带说明文字的行**上（如
> `B09MVVGKPW,,amazon.com,,amazon.com`）。因为说明文字在**第 5 列**，服务端只取前 3 列，
> **此项非致命**。

**⇒ 文件无罪，商品无罪。**

## 二、⭐ 决定性的机制（从页面源码扒出，不是猜的）

建单页是**老版 jQuery + React dropzone**（挂载点 `#asinFileUploaderContainer`）。上传相关接口：

| 用途 | 接口 |
|---|---|
| 上传文件 | `POST /dsp/rdo/api/upload-asin-file?csrfAuthToken=<渲染时内嵌> ` |
| 关联任务状态 | `GET /dsp/rdo/api/asin-association-status` |
| 已关联数量 | `GET /dsp/<ENTITY>/rdo/api/asin-count` |
| 下载官方模板 | `GET /dsp/rdo/api/asin-bulk-upload-file-template?entityId=<ENTITY>` |

**两条关键机制：**

1. **上传 ≠ 关联。** 源码注释原文：
   > *"there is no actual asin association happening in this step.
   > Actual asin association happens in save"*
   → 上传只把 CSV 存下来、换一个 `fileId`；**真正的 ASIN 关联发生在「保存订单」时**。
   所以"上传后仍显示 No Product."在保存前属正常。

2. **上传失败的判定条件**：`onUploadCompleted(result)` 里 **`result` 为空或没有 `fileId`**
   → 组件**把已选文件丢掉**（清空 file input），界面回到初始的
   `Drop .csv file to upload` + `No Product.`。
   👉 **截图正是这个状态**（文件消失 + No Product.）
   ⇒ **是上传请求失败，不是文件内容被拒。**

   ⚠️ 反向印证：**文件内容有问题走的是另一条路** ——
   `invalidDomainAsinSize` / `invalidFormatAsinSize` / `duplicateAsinSize`
   → 只弹一条"部分未添加"的警告列表，**但仍然会拿到 `fileId`、文件不会被丢弃**。

## 三、站点复选框：最可能的人为漏步

`添加商品 → 亚马逊域 → 选择站点` 是一组复选框：
`amazon.com`(=1) / `amazon.ca`(=7) / `amazon.com.br` / `amazon.com.mx` /
`Prime Now US` / `Prime Now CA` / `Fresh Stores US` / `Whole Foods Market US`。

**实测空白新建订单页：8 个站点 `checked` 全为 `false`**（默认不勾），
且页面自带告警：**`选择一个或多个亚马逊站点`**。

→ 排查上传/关联类故障时**先看这组勾选**：站点没勾，即使上传成功，后续也关联不上。

## 四、尚未定因 → 三个候选 + 各自判据

| # | 候选原因 | 判据 / 验证方式 |
|---|---|---|
| 1 | **CSRF / 会话过期**（`csrfAuthToken` 是页面渲染时内嵌的，页面开久或会话轮换即 403） | **刷新页面后重传**，多半直接就好（最省事，建议先试） |
| 2 | **站点（亚马逊域）未勾选** | 看 `选择站点` 那组勾选；勾上 `amazon.com` 再传 |
| 3 | **店铺级网络/代理**（川鹏是项目里唯一稳定崩坏的店；`orderMFEWebsiteVendors.chunk.js` 确认在本页加载列表内） | 换节点/重开窗口；或换一家店做对照 |
| — | **判据（最快）** | 按 **F12 → Network**，找 `upload-asin-file` 请求的 **HTTP 状态码**：<br>`403` = CSRF/会话；`5xx` = 服务端；**请求根本没发出去/失败** = 网络/代理 |
